2. OOP Principles

Q1. Explain OOP principles.

OOP is a programming approach where software is designed using objects that contain data and behavior. Main principles are encapsulation, abstraction, inheritance and polymorphism.

  • Encapsulation: Hide internal state and expose controlled methods. Example: Order status should change through ConfirmOrder(), not direct field update.
  • Abstraction: Hide implementation details. Example: IPaymentGateway.Pay() hides provider-specific logic.
  • Inheritance: Reuse common behavior from parent class, but avoid overuse.
  • Polymorphism: Same interface, different implementation. Example: Email and SMS both implement INotification.Send().

Q2. Interface vs Abstract Class?

Interface defines a contract and is best for loose coupling and dependency injection. Abstract class can provide common implementation and shared state. Use interface for capability and abstract class for shared base behavior.

3. Memory, References and Immutability

Q1. Value type vs Reference type?

Value type stores actual value, like int, bool, struct. Reference type stores address/reference of object, like class, array and object. Assigning reference type copies reference, not actual object.

Q2. What is immutability?

Immutable object cannot be changed after creation. In C#, string is immutable. Any modification creates a new string object.

Q3. Shallow copy vs Deep copy?

  • Shallow copy: Copies top-level object only. Nested objects may still be shared.
  • Deep copy: Copies complete object graph including nested objects.
Interview line: Immutability reduces side effects and makes code safer in concurrent scenarios.

4. JavaScript Execution and References

Q1. Output and reason?

const a = { x: 3 };
const b = a;

b.x = 5;

console.log(a.x);

Output: 5

Reason: Objects are assigned by reference. a and b point to the same object. So changing b.x also affects a.x.

Q2. How to avoid impact between objects?

const b = { ...a }; // shallow copy

const b = structuredClone(a); // deep copy for supported values

Functions are not cloned by structuredClone(). JSON deep copy removes functions.

Q3. const array output?

const a = [];
a.push(10);
console.log(a);

Output: [10]

const prevents reassignment, not mutation.

Q4. const object output?

const a = {};
a['x'] = 1;
a.y = 2;
console.log(a);

Output: { x: 1, y: 2 }

Object properties can be added because object reference is same.

Q5. Event loop output?

console.log('A');

setTimeout(() => console.log('B'), 0);

Promise.resolve().then(() => console.log('C'));

console.log('D');

// Output: A D C B

Sync code runs first. Promise callback goes to microtask queue, and setTimeout goes to macrotask queue. Microtask runs before macrotask.

5. Async Flow

Q1. What is async/await?

async/await allows non-blocking asynchronous execution. In .NET, async methods usually return Task or Task<T>. It does not always create a new thread.

Q2. Task vs Thread?

Thread is an actual execution resource. Task represents asynchronous work. For I/O operations, async can release the thread while waiting.

Q3. Exception flow in async?

try
{
    await SomeAsyncMethod();
}
catch(Exception ex)
{
    // exception is caught here when awaited
}

Exception inside async method is captured in Task and re-thrown when awaited.

Risk signal: Saying async always creates a new thread is incorrect.

6. ACID and Transactions

Q1. Explain ACID.

  • Atomicity: All operations succeed or all fail.
  • Consistency: Database remains in valid state.
  • Isolation: Parallel transactions do not corrupt each other.
  • Durability: Committed data remains saved.

Q2. Implement ACID in C#.

await using var transaction = await db.Database.BeginTransactionAsync();

try
{
    db.Orders.Add(order);
    await db.SaveChangesAsync();

    db.Payments.Add(payment);
    await db.SaveChangesAsync();

    await transaction.CommitAsync();
}
catch
{
    await transaction.RollbackAsync();
    throw;
}
Microservices note: Across multiple databases, strict ACID is difficult. Use eventual consistency, outbox pattern, idempotency and retries.

7. Garbage Collection

Q1. Explain GC generations.

.NET GC manages managed memory. New objects start in Gen 0. Surviving objects move to Gen 1 and Gen 2. Long-lived objects are collected less frequently. Large objects go to LOH.

Q2. IDisposable vs GC?

GC cleans managed memory. IDisposable releases unmanaged resources like DB connections, streams, file handles and sockets.

using var connection = new SqlConnection(connectionString);
connection.Open();

8. REST Semantics

Q1. Explain HTTP verbs.

  • GET: Read data, should not modify state.
  • POST: Create resource or trigger action.
  • PUT: Full update/replace.
  • PATCH: Partial update.
  • DELETE: Delete resource.

Q2. Important status codes?

  • 200 OK
  • 201 Created
  • 204 No Content
  • 400 Bad Request
  • 401 Unauthorized
  • 403 Forbidden
  • 404 Not Found
  • 409 Conflict
  • 500 Internal Server Error

9. Entity Framework Performance and N+1

Q1. What is N+1 problem?

N+1 happens when one query loads parent records and then separate query runs for each related record, causing many database calls.

// Risky with lazy loading
var orders = context.Orders.ToList();

foreach(var order in orders)
{
    Console.WriteLine(order.Customer.Name);
}

Q2. How to fix?

var orders = context.Orders
    .Include(o => o.Customer)
    .ToList();

var result = context.Orders
    .AsNoTracking()
    .Select(o => new OrderDto
    {
        Id = o.Id,
        CustomerName = o.Customer.Name
    })
    .ToList();

EF Performance Checklist

  • Use projection using Select.
  • Use AsNoTracking() for read-only queries.
  • Use pagination.
  • Avoid unnecessary Include.
  • Check generated SQL.
  • Add proper indexes.
  • Avoid early ToList().

10. Microservices

Q1. Sync vs Async communication?

Sync: REST/gRPC call and wait for response. Use when immediate response is needed.

Async: Publish message/event and process later. Use when eventual processing is acceptable.

Trade-off

  • Sync is simple but creates runtime dependency and cascading failure risk.
  • Async improves resilience but adds eventual consistency and message handling complexity.

Q2. What is CQRS?

CQRS separates commands and queries. Commands change state, queries read data. Use when read and write models differ in complexity or performance needs.

Q3. Failure handling in microservices?

  • Retry with backoff
  • Timeout
  • Circuit breaker
  • Dead-letter queue
  • Idempotency
  • Outbox pattern
  • Correlation ID
  • Centralized logging and monitoring

Q4. Why delegate is not used between microservices?

Delegate works inside same process and memory. Microservices are separate processes. Between services we use REST, gRPC or message broker like RabbitMQ/Kafka/Azure Service Bus.

11. RabbitMQ and Idempotency

Q1. Explain RabbitMQ flow.

Producer sends message to exchange. Exchange routes message to queue. Consumer reads from queue and sends acknowledgement after successful processing.

Q2. Ack, Nack and DLQ?

  • Ack: successful processing confirmation.
  • Nack: processing failed.
  • DLQ: dead-letter queue stores failed messages after retry.

Q3. What is idempotency?

Idempotency means same request/message processed multiple times should not create duplicate side effects.

if (AlreadyProcessed(message.Id))
{
    return;
}

Process(message);
MarkProcessed(message.Id);

12. Authentication, Authorization, JWT and OAuth

Q1. Authentication vs Authorization?

Authentication: Who are you?

Authorization: What are you allowed to access?

Q2. JWT lifecycle?

  1. User logs in.
  2. Server validates credentials.
  3. Server issues JWT with claims and expiry.
  4. Client sends token in Authorization: Bearer token.
  5. API validates signature, issuer, audience and expiry.
  6. API checks claims, roles and policies.

Q3. OAuth flows?

  • Authorization Code + PKCE: user login for SPA/web app.
  • Client Credentials: service-to-service authentication.
  • Refresh Token: renew access token.

Q4. Secure API practices?

  • Use HTTPS.
  • Validate JWT fully.
  • Use role/policy-based authorization.
  • Validate input.
  • Use rate limiting.
  • Do not log sensitive data.
  • Store secrets in Key Vault/secret manager.

13. Angular and SPA

Q1. What is SPA?

SPA loads a single page and updates UI dynamically without full page reload. Angular manages components, routing, templates and data binding.

Q2. Lifecycle hooks?

  • ngOnInit: initialization.
  • ngOnChanges: input changes.
  • ngAfterViewInit: view initialized.
  • ngOnDestroy: cleanup.

Q3. Angular bindings?

  • Interpolation: {{ value }}
  • Property binding: [disabled]="isDisabled"
  • Event binding: (click)="save()"
  • Two-way binding: [(ngModel)]="name"

Q4. Observable vs Promise?

Promise returns a single future value. Observable can emit multiple values over time, is lazy, cancellable using unsubscribe and supports RxJS operators.

14. DI Scope, Azure Services and Secrets

Q1. DI scopes?

  • Transient: new instance every time.
  • Scoped: one instance per HTTP request. Good for DbContext.
  • Singleton: one instance for application lifetime. Avoid request-specific state.

Q2. When to use which Azure service?

  • App Service: host APIs/web apps.
  • Azure Functions: serverless/event-driven jobs.
  • Service Bus: enterprise messaging queues/topics.
  • Storage Account: blobs/files/queues.
  • Key Vault: secrets, certificates and keys.
  • Application Insights: telemetry and monitoring.

Q3. Secrets vs Config?

Config is non-sensitive, like API URL, timeout and feature flag. Secrets are sensitive, like password, API key, connection string and certificate. Secrets should be stored in Key Vault or secret manager.

15. Coding Question: Move Zeros to End

Q. Move zeros to end, output should be 24500.

int[] arr = { 0, 2, 0, 4, 5 };

int index = 0;

for (int i = 0; i < arr.Length; i++)
{
    if (arr[i] != 0)
    {
        arr[index++] = arr[i];
    }
}

while (index < arr.Length)
{
    arr[index++] = 0;
}

Console.WriteLine(string.Join("", arr)); // 24500

Problem in wrong code: If you write arr[index] = 0; without index++, it will become an infinite loop.
