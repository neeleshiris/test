1. Multi-Slicer Bread Toaster: End-to-End Design

Question

Design a system for a multi-slicer bread toaster. Number of slicers is not fixed. Include real toaster controls: push/pull lever, cancel button, modes like defrost and reheat, and behavior when toast comes out.

How to start in interview

“Since slicer count is not fixed, I will not hardcode slots. I will model each slicer as an independent object with state, position, heater, sensor and push/pull mechanism. Toaster will manage a dynamic list of slicers. PushDown moves bread inside. Cancel stops heating and ejects bread. Completion/error also turns off heater and ejects bread. Modes like Normal, Defrost and Reheat are handled using profile strategy.”

Functional requirements

  • Support N slicers dynamically.
  • Each slicer can independently move down/inside and up/ejected.
  • Push/Pull lever moves bread down/inside before heating starts.
  • Cancel button stops heating and ejects bread immediately.
  • On successful completion, bread ejects automatically.
  • On jam/overheat/error, heater turns off and bread ejects.
  • Modes: Normal, Defrost, Reheat.
  • Support concurrent toasting for multiple slicers.
  • Code should be testable by mocking heater, mechanism and sensor.

Non-functional requirements

  • Extensible: add more slicers or modes without changing core slicer logic.
  • Safe: heater must always turn off in finally block.
  • Maintainable: separate mechanical movement, heating, sensing and profile logic.
  • Testable: use interfaces.

Architecture

User Control Panel |-- Select Mode: Normal / Defrost / Reheat |-- Select Browning Level |-- PushDown(slot/all) |-- Cancel(slot/all) Toaster |-- List<Slicer> dynamic |-- ToastProfileStrategy |-- ToastAllAsync() |-- CancelSlicer(id) Slicer |-- State: Empty, BreadInserted, PushedDown, Toasting, Completed, Cancelled, Jammed, Overheated, Error |-- Position: UpEjected / DownInside |-- Heater: TurnOn / TurnOff |-- Mechanism: PushDown / Eject |-- Sensor: BreadInserted / Jammed / Temperature Important flow: PushDown -> Position DownInside -> Heater ON -> Toasting loop Cancel/Complete/Error -> Heater OFF -> Eject -> Position UpEjected

Patterns used

  • Factory Pattern: create N slicers dynamically.
  • Strategy Pattern: Normal/Defrost/Reheat profile calculation.
  • State Pattern / State enum: slicer state transitions.
  • Dependency Injection: inject heater, sensor and mechanism.
  • Command-like operations: PushDown, Cancel, Eject.

Program.cs

using System;
using System.Collections.Generic;
using System.Linq;
using System.Threading;
using System.Threading.Tasks;

namespace MultiSlicerToasterV2;

public enum SlicerState
{
    Empty,
    BreadInserted,
    PushedDown,
    Toasting,
    Completed,
    Cancelled,
    Jammed,
    Overheated,
    Error
}

public enum SlicerPosition
{
    UpEjected,
    DownInside
}

public enum ToastMode
{
    Normal,
    Defrost,
    Reheat
}

public sealed class ToastProfile
{
    public ToastMode Mode { get; init; }
    public int BrowningLevel { get; init; }
    public int DurationInSeconds { get; init; }
    public int Temperature { get; init; }
}

public interface IHeater
{
    void TurnOn(int slicerId, int temperature);
    void TurnOff(int slicerId);
}

public sealed class ConsoleHeater : IHeater
{
    public void TurnOn(int slicerId, int temperature)
        => Console.WriteLine($"[Slicer {slicerId}] Heater ON at {temperature}°C");

    public void TurnOff(int slicerId)
        => Console.WriteLine($"[Slicer {slicerId}] Heater OFF");
}

public interface ISlicerMechanism
{
    void PushDown(int slicerId);
    void Eject(int slicerId);
}

public sealed class PushPullMechanism : ISlicerMechanism
{
    public void PushDown(int slicerId)
        => Console.WriteLine($"[Slicer {slicerId}] Push/Pull lever pressed: bread moved DOWN/INSIDE.");

    public void Eject(int slicerId)
        => Console.WriteLine($"[Slicer {slicerId}] Bread moved UP/EJECTED.");
}

public interface ISlicerSensor
{
    bool IsBreadInserted(int slicerId);
    bool IsJammed(int slicerId);
    int GetTemperature(int slicerId);
}

public sealed class DemoSlicerSensor : ISlicerSensor
{
    private readonly Random _random = new();
    private readonly HashSet<int> _jammedSlicers;

    public DemoSlicerSensor(IEnumerable<int>? jammedSlicers = null)
    {
        _jammedSlicers = jammedSlicers?.ToHashSet() ?? new HashSet<int>();
    }

    public bool IsBreadInserted(int slicerId) => true;
    public bool IsJammed(int slicerId) => _jammedSlicers.Contains(slicerId);
    public int GetTemperature(int slicerId) => _random.Next(120, 220);
}

public interface IToastProfileStrategy
{
    ToastProfile CreateProfile(ToastMode mode, int browningLevel);
}

public sealed class ToastProfileStrategy : IToastProfileStrategy
{
    public ToastProfile CreateProfile(ToastMode mode, int browningLevel)
    {
        browningLevel = Math.Clamp(browningLevel, 1, 5);

        return mode switch
        {
            ToastMode.Normal => new ToastProfile
            {
                Mode = ToastMode.Normal,
                BrowningLevel = browningLevel,
                DurationInSeconds = browningLevel + 2,
                Temperature = 140 + browningLevel * 15
            },
            ToastMode.Defrost => new ToastProfile
            {
                Mode = ToastMode.Defrost,
                BrowningLevel = browningLevel,
                DurationInSeconds = browningLevel + 4,
                Temperature = 130 + browningLevel * 10
            },
            ToastMode.Reheat => new ToastProfile
            {
                Mode = ToastMode.Reheat,
                BrowningLevel = browningLevel,
                DurationInSeconds = 2,
                Temperature = 120
            },
            _ => throw new NotSupportedException($"Unsupported mode: {mode}")
        };
    }
}

public sealed class Slicer
{
    private readonly IHeater _heater;
    private readonly ISlicerMechanism _mechanism;
    private readonly ISlicerSensor _sensor;
    private CancellationTokenSource? _currentToastingCts;

    public int Id { get; }
    public SlicerState State { get; private set; } = SlicerState.Empty;
    public SlicerPosition Position { get; private set; } = SlicerPosition.UpEjected;

    public Slicer(int id, IHeater heater, ISlicerMechanism mechanism, ISlicerSensor sensor)
    {
        Id = id;
        _heater = heater;
        _mechanism = mechanism;
        _sensor = sensor;
    }

    public async Task PushDownAndToastAsync(ToastProfile profile, CancellationToken externalToken)
    {
        _currentToastingCts = CancellationTokenSource.CreateLinkedTokenSource(externalToken);
        CancellationToken token = _currentToastingCts.Token;

        try
        {
            Console.WriteLine($"\n[Slicer {Id}] Requested Mode={profile.Mode}, Level={profile.BrowningLevel}");

            if (!_sensor.IsBreadInserted(Id))
            {
                State = SlicerState.Empty;
                Position = SlicerPosition.UpEjected;
                Console.WriteLine($"[Slicer {Id}] Bread not inserted. Cannot start.");
                return;
            }

            State = SlicerState.BreadInserted;
            PushDown();

            State = SlicerState.Toasting;
            _heater.TurnOn(Id, profile.Temperature);

            for (int second = 1; second <= profile.DurationInSeconds; second++)
            {
                token.ThrowIfCancellationRequested();

                if (_sensor.IsJammed(Id))
                {
                    State = SlicerState.Jammed;
                    throw new InvalidOperationException($"Bread jam detected in slicer {Id}.");
                }

                int currentTemperature = _sensor.GetTemperature(Id);
                if (currentTemperature > 240)
                {
                    State = SlicerState.Overheated;
                    throw new InvalidOperationException($"Overheat detected in slicer {Id}.");
                }

                Console.WriteLine($"[Slicer {Id}] Toasting {second}/{profile.DurationInSeconds}, Temp={currentTemperature}°C");
                await Task.Delay(700, token);
            }

            State = SlicerState.Completed;
            Console.WriteLine($"[Slicer {Id}] Toast completed.");
        }
        catch (OperationCanceledException)
        {
            State = SlicerState.Cancelled;
            Console.WriteLine($"[Slicer {Id}] Cancel button pressed. Toasting cancelled.");
        }
        catch (Exception ex)
        {
            if (State != SlicerState.Jammed && State != SlicerState.Overheated)
                State = SlicerState.Error;

            Console.WriteLine($"[Slicer {Id}] ERROR: {ex.Message}");
        }
        finally
        {
            // Safety guarantee: heater must be OFF in success, cancel, jam, overheat or error.
            _heater.TurnOff(Id);

            // If bread is inside, eject it outside.
            if (Position == SlicerPosition.DownInside)
                Eject();

            _currentToastingCts?.Dispose();
            _currentToastingCts = null;
        }
    }

    public void Cancel()
    {
        if (State == SlicerState.Toasting || Position == SlicerPosition.DownInside)
            _currentToastingCts?.Cancel();
        else
            Console.WriteLine($"[Slicer {Id}] Cancel ignored because slicer is not active.");
    }

    private void PushDown()
    {
        Position = SlicerPosition.DownInside;
        State = SlicerState.PushedDown;
        _mechanism.PushDown(Id);
    }

    private void Eject()
    {
        Position = SlicerPosition.UpEjected;
        _mechanism.Eject(Id);
    }
}

public sealed class Toaster
{
    private readonly List<Slicer> _slicers;
    private readonly IToastProfileStrategy _profileStrategy;

    public Toaster(IEnumerable<Slicer> slicers, IToastProfileStrategy profileStrategy)
    {
        _slicers = slicers.ToList();
        _profileStrategy = profileStrategy;
    }

    public async Task ToastAllAsync(ToastMode mode, int browningLevel, CancellationToken token)
    {
        ToastProfile profile = _profileStrategy.CreateProfile(mode, browningLevel);
        Console.WriteLine($"\nToaster started with {_slicers.Count} slicers. Mode={mode}\n");

        var tasks = _slicers.Select(s => s.PushDownAndToastAsync(profile, token)).ToList();

        // Demo cancellation: cancel slicer 1 after 2 seconds to prove cancel ejects bread.
        _ = Task.Run(async () =>
        {
            await Task.Delay(2000);
            if (_slicers.Count >= 1)
                CancelSlicer(1);
        });

        await Task.WhenAll(tasks);
        PrintSummary();
    }

    public void CancelSlicer(int slicerId)
    {
        var slicer = _slicers.FirstOrDefault(s => s.Id == slicerId);
        if (slicer == null)
        {
            Console.WriteLine($"Slicer {slicerId} not found.");
            return;
        }

        Console.WriteLine($"\n[Toaster] Cancel requested for slicer {slicerId}.");
        slicer.Cancel();
    }

    private void PrintSummary()
    {
        Console.WriteLine("\nFinal Status:");
        foreach (var slicer in _slicers)
            Console.WriteLine($"Slicer {slicer.Id}: State={slicer.State}, Position={slicer.Position}");
    }
}

public static class ToasterFactory
{
    public static Toaster Create(int slicerCount, IEnumerable<int>? jammedSlicers = null)
    {
        if (slicerCount <= 0)
            throw new ArgumentException("Slicer count must be greater than zero.");

        IHeater heater = new ConsoleHeater();
        ISlicerMechanism mechanism = new PushPullMechanism();
        ISlicerSensor sensor = new DemoSlicerSensor(jammedSlicers);
        IToastProfileStrategy strategy = new ToastProfileStrategy();

        var slicers = Enumerable.Range(1, slicerCount)
            .Select(id => new Slicer(id, heater, mechanism, sensor));

        return new Toaster(slicers, strategy);
    }
}

public class Program
{
    public static async Task Main()
    {
        Console.WriteLine("Multi-Slicer Toaster V2: Push/Pull + Cancel/Eject + Modes");
        Console.WriteLine("---------------------------------------------------------");

        Console.Write("Enter number of slicers: ");
        int slicerCount = int.TryParse(Console.ReadLine(), out int count) ? count : 4;

        Console.Write("Enter browning level 1-5: ");
        int browningLevel = int.TryParse(Console.ReadLine(), out int level) ? level : 3;

        Console.WriteLine("Select mode: 1=Normal, 2=Defrost, 3=Reheat");
        Console.Write("Enter mode: ");
        int modeInput = int.TryParse(Console.ReadLine(), out int modeValue) ? modeValue : 1;

        ToastMode mode = modeInput switch
        {
            2 => ToastMode.Defrost,
            3 => ToastMode.Reheat,
            _ => ToastMode.Normal
        };

        // Demo: slicer 2 is jammed if available, to show error + eject behavior.
        var jammed = slicerCount >= 2 ? new[] { 2 } : Array.Empty<int>();
        Toaster toaster = ToasterFactory.Create(slicerCount, jammedSlicers: jammed);

        using var cts = new CancellationTokenSource();
        await toaster.ToastAllAsync(mode, browningLevel, cts.Token);

        Console.WriteLine("\nDone. Press any key to exit.");
        Console.ReadKey();
    }
}

4. Toaster Explanation + Cross Questions

Cancel button behavior

Cancel calls CancellationTokenSource.Cancel. The running toasting loop receives cancellation, OperationCanceledException is caught, State becomes Cancelled, heater turns off in finally, and Eject moves bread outside.

Why finally block?

Because heater and mechanical ejection are safety-critical. Whether toast completes, fails, jams, overheats, or cancels, heater must turn off and bread should come out.

Why mechanism interface?

Push/Pull is mechanical behavior. Heating is different responsibility. Keeping ISlicerMechanism separate follows SRP and helps testing.

What if one slicer jams?

Current design isolates failure to that slicer. Jammed slicer stops and ejects. Other slicers continue. For critical safety issue, add SafetyController to cancel all slicers.

What if new mode Bagel is added?

Add new enum value and profile logic or create separate strategy class. Slicer logic does not change.

5. .NET Memory Management / GC

Explain memory management

.NET memory management is handled by CLR. Reference type objects are allocated on managed heap. Garbage Collector identifies unreachable objects and reclaims memory. However unmanaged resources such as file handles, database connections, sockets and native handles need deterministic cleanup using IDisposable/using.

Stack vs Heap

StackHeap
Method call frames, local variables, references.Reference type objects.
Thread-specific and fast.Managed by GC.
Cleaned when method returns.Cleaned when object becomes unreachable.
int x = 10;       // local value context
Person p = new(); // p reference in stack frame, Person object on heap
Do not say all value types are always on stack. Value types can be on heap when boxed, in arrays, as fields of reference types, or captured in closures.

Generations

  • Gen 0: new short-lived objects.
  • Gen 1: objects that survived Gen 0.
  • Gen 2: long-lived objects; collection is expensive.

GC uses generations because most objects die young. This improves performance by collecting young objects frequently and old objects less frequently.

GC phases

  1. Mark: find reachable objects from GC roots.
  2. Sweep: unreachable objects are garbage.
  3. Compact: move live objects together to reduce fragmentation.
  4. Update references: fix references after movement.

6. Heap Deep Dive

Managed heap

Managed heap stores objects allocated by CLR. Allocation is usually fast using allocation pointer. When memory pressure increases, GC runs and cleans unreachable objects.

SOH / LOH / POH

HeapMeaning
SOHSmall Object Heap for normal small objects.
LOHLarge Object Heap for objects around 85 KB or more, collected with Gen 2.
POHPinned Object Heap for pinned objects in modern .NET.
byte[] small = new byte[10_000];
byte[] large = new byte[100_000]; // likely LOH

GC roots

GC roots are starting references used to determine object reachability: stack locals, static fields, CPU registers, GC handles, finalizer queue references.

Fragmentation

Fragmentation means free memory exists but scattered. Compaction moves live objects together. Pinned objects can increase fragmentation because GC cannot move them.

7. Resources / IDisposable / Memory Leaks

Managed vs unmanaged resources

  • Managed: normal .NET objects.
  • Unmanaged: file handles, sockets, DB connections, native memory, OS handles.

IDisposable

Use IDisposable and using for deterministic cleanup.

using var stream = new FileStream("data.txt", FileMode.OpenOrCreate);
// Dispose automatically called at end of scope

Finalizer

Finalizer is a non-deterministic safety net. Prefer IDisposable and SafeHandle. Finalizer can delay cleanup because the object may survive one extra GC cycle.

Memory leaks in .NET

Leak happens when object is no longer needed but still reachable, so GC cannot collect it.

  • Static lists/dictionaries growing forever.
  • Event handlers not unsubscribed.
  • Timers keeping references alive.
  • Unbounded cache.
  • Not disposing streams/connections.
public static List<byte[]> Cache = new();
// If continuously added and never removed, objects stay reachable.

8. Promise vs Observable

Core difference

PromiseObservable
Single value/error.Zero, one or multiple values over time.
Eager: starts immediately.Lazy: starts when subscribed.
Not directly cancellable.Cancellable using unsubscribe.
Limited operators.RxJS operators like map, filter, switchMap, retry.

Multiple emit meaning

Observable is stream-based. It can emit many values over time. Examples: search input, route params, WebSocket, form valueChanges.

interval(1000).subscribe(value => console.log(value));
// 0, 1, 2, 3... every second

Promise eager vs Observable lazy

const p = new Promise(resolve => {
  console.log('Promise starts immediately');
  resolve(1);
});

const o$ = new Observable(sub => {
  console.log('Observable starts on subscribe');
  sub.next(1);
  sub.complete();
});

o$.subscribe();

9. RxJS Scenario Questions

Search box API call

Observable is better because search input emits multiple values. Use debounceTime to wait, distinctUntilChanged to avoid duplicate terms, and switchMap to cancel previous API call.

this.searchControl.valueChanges.pipe(
  debounceTime(300),
  distinctUntilChanged(),
  switchMap(term => this.productService.search(term))
).subscribe(products => this.products = products);

Why Angular HTTP returns Observable though HTTP emits once?

Because Observable supports cancellation, retry, error handling, transformation and composition.

this.http.get<Product[]>('/api/products').pipe(
  retry(2),
  catchError(err => of([]))
).subscribe(data => this.products = data);

switchMap / mergeMap / concatMap

  • switchMap: latest only; best for search.
  • mergeMap: parallel inner calls.
  • concatMap: ordered one-by-one calls.

Subject vs BehaviorSubject

Subject has no initial value. BehaviorSubject stores latest value and emits it to new subscribers.

private userSubject = new BehaviorSubject<User | null>(null);
user$ = this.userSubject.asObservable();

setUser(user: User) {
  this.userSubject.next(user);
}

10. Angular Dependency Injection

Explain DI

Dependency Injection means Angular creates and provides dependencies to classes. Components do not manually create services. This improves loose coupling, reusability and testability.

@Injectable({ providedIn: 'root' })
export class AuthService {
  isLoggedIn(): boolean {
    return !!localStorage.getItem('token');
  }
}

@Component({ selector: 'app-header', template: '' })
export class HeaderComponent {
  constructor(private authService: AuthService) {}
}

Hierarchical injector

Angular first checks current component injector, then parent injector, then route/module/environment/root injector. Closest provider wins.

Component Injector ↓ Parent Injector ↓ Route / Module / Environment Injector ↓ Root Injector

providedIn root

Creates one singleton app-level instance unless a child/component injector overrides it.

11. DI Cross Questions

Same service in root and component level

If service is provided in root and also in component providers, Angular creates a new instance for that component subtree. Parent and children use component-level instance; other components use root instance.

@Injectable({ providedIn: 'root' })
export class CounterService { count = 0; }

@Component({
  selector: 'app-parent',
  template: '<app-child></app-child>',
  providers: [CounterService]
})
export class ParentComponent {
  constructor(public counter: CounterService) {
    counter.count++;
  }
}

@Component({ selector: 'app-child', template: '' })
export class ChildComponent {
  constructor(public counter: CounterService) {}
}

When to use component-level provider?

  • Need isolated state per component instance.
  • Wizard/form state should reset on component destroy.
  • Multiple tabs/cards should not share state.

@Self, @SkipSelf, @Optional

  • @Self: current injector only.
  • @SkipSelf: skip current injector and search parent.
  • @Optional: return null instead of throwing if not found.

12. Angular Auth Guard

Explain Auth Guard

Auth Guard protects routes before navigation. It can allow, block, or redirect. It can return boolean, UrlTree, Promise or Observable.

export const authGuard: CanActivateFn = (route, state) => {
  const auth = inject(AuthService);
  const router = inject(Router);

  if (auth.isLoggedIn()) return true;

  return router.createUrlTree(['/login'], {
    queryParams: { returnUrl: state.url }
  });
};

Observable-based guard

export const authGuard: CanActivateFn = () => {
  const auth = inject(AuthService);
  const router = inject(Router);

  return auth.currentUser$.pipe(
    take(1),
    map(user => user ? true : router.createUrlTree(['/login']))
  );
};
Use take(1), otherwise navigation can hang if the stream never completes.

Role guard

export const roleGuard: CanActivateFn = (route) => {
  const auth = inject(AuthService);
  const router = inject(Router);
  const requiredRole = route.data['role'];

  return auth.currentUser$.pipe(
    take(1),
    map(user => user?.roles?.includes(requiredRole)
      ? true
      : router.createUrlTree(['/unauthorized']))
  );
};

13. Auth Guard Cross Questions

Guard vs Interceptor

GuardInterceptor
Controls route/page access.Controls HTTP request/response.
Runs before component activation.Runs when HTTP call happens.
Redirects unauthenticated users.Adds token, handles 401, refresh token.

Token expired: guard or interceptor?

Guard can pre-check token before route load. Interceptor should handle API 401 globally, refresh token if supported, retry or logout.

Is guard enough for security?

No. Guard is client-side only. Backend must validate JWT signature, issuer, audience, expiry and roles/claims.

canActivate vs canMatch vs canDeactivate

  • canActivate: route activation.
  • canMatch: route matching/lazy route access.
  • canActivateChild: child route protection.
  • canDeactivate: prevent leaving page, e.g., unsaved changes.

14. Final Short Answers

Toaster

“I model toaster as a controller of dynamic slicer collection. Each slicer has state, position, heater, sensor and mechanism. PushDown moves bread inside, Cancel stops heating and ejects bread. Mode strategy handles Normal/Defrost/Reheat. Finally block guarantees heater off and eject on completion/cancel/error.”

GC

“.NET GC manages managed heap objects using generations. It tracks reachable objects from GC roots. Unreachable objects are collected and heap may compact. GC does not deterministically release unmanaged resources, so IDisposable is required.”

Observable

“Promise emits one value and starts immediately. Observable is lazy, cancellable, and can emit multiple values over time. Best examples are search box, WebSocket, route params, and form valueChanges.”

DI

“providedIn root gives singleton app-wide instance. Component providers create separate instance for that component subtree and override root instance there.”

Auth Guard

“Guard protects routes and can return boolean/UrlTree/Observable/Promise. It improves UX but backend must enforce real security. Interceptor handles token on HTTP calls.”
