2) AZ-900: Azure Fundamentals Interview Q&A

Cloud ConceptsComputeStorageNetworkingSecurityGovernance
1. What is cloud computing?
Cloud computing means delivering compute, storage, networking, databases and software over the internet. Instead of buying physical servers, we consume resources on demand and pay based on usage.
2. What are the main benefits of cloud?
Major benefits are scalability, high availability, reliability, disaster recovery, global reach, security, governance and cost optimization through pay-as-you-go pricing.
3. Difference between IaaS, PaaS and SaaS?
IaaS: We manage OS/runtime/app; Azure manages hardware. Example: VM. PaaS: Azure manages platform; we deploy app. Example: App Service. SaaS: Complete software managed by provider. Example: Microsoft 365.
4. What is shared responsibility model?
Security responsibility is shared between cloud provider and customer. In IaaS customer manages more things like OS and app. In PaaS less. In SaaS provider manages most of the stack, while customer manages data, identity and access.
5. What is Azure Region?
An Azure region is a geographic area containing one or more datacenters. We deploy resources in a region based on latency, compliance and availability needs.
6. What is Availability Zone?
Availability Zones are physically separate datacenter locations within a region. They help protect applications from datacenter-level failures.
7. What is Resource Group?
A resource group is a logical container for Azure resources like App Service, Storage, SQL and Key Vault. It helps manage lifecycle, access and cost for related resources.
8. What is Azure App Service?
Azure App Service is a PaaS offering to host web apps, APIs and backend services without managing servers. It supports scaling, deployment slots, custom domains and SSL.
9. What is Azure Function?
Azure Functions is serverless compute. We write small pieces of code that run based on triggers like HTTP request, timer, queue message or blob upload. It is useful for event-driven processing.
10. App Service vs Azure Functions?
App Service is better for continuously running web apps/APIs. Azure Functions is better for short, event-driven tasks where we want serverless execution and consumption-based cost.
11. What is Azure Storage?
Azure Storage is a scalable cloud storage service. It includes Blob Storage for objects/files, File Storage for shared file system, Queue Storage for messages and Table Storage for NoSQL key-value data.
12. Blob Storage tiers?
Hot tier is for frequently accessed data, Cool tier for infrequently accessed data, Archive tier for rarely accessed long-term data. Selection depends on access pattern and cost.
13. What is VNet?
Azure Virtual Network is a private network in Azure. It allows Azure resources to communicate securely with each other, internet and on-premises networks.
14. VPN Gateway vs ExpressRoute?
VPN Gateway connects on-premises to Azure over encrypted internet tunnel. ExpressRoute provides private dedicated connectivity, better for enterprise workloads needing predictable latency and higher reliability.
15. What is Microsoft Entra ID?
Microsoft Entra ID, earlier known as Azure Active Directory, is Microsoft’s cloud identity and access management service used for authentication, authorization, MFA and conditional access.
16. What is MFA?
Multi-Factor Authentication adds extra verification like OTP, authenticator app or biometric along with password. It reduces risk if password is compromised.
17. What is RBAC?
Role-Based Access Control gives users/groups/service principals permissions based on roles like Reader, Contributor or Owner at subscription, resource group or resource level.
18. What is Azure Policy?
Azure Policy enforces organizational rules. Example: allow resources only in approved regions, require tags, or deny public IP creation.
19. What is Azure Monitor?
Azure Monitor collects metrics and logs from applications and infrastructure. It helps with alerting, troubleshooting and performance analysis.
20. What is Cost Management?
Azure Cost Management helps track usage, analyze spend, create budgets and set alerts to control cloud cost.

3) AZ-204: Azure Developer Interview Q&A

App ServiceFunctionsStorageCosmos DBKey VaultService BusMonitoring
1. How do you deploy a .NET API to Azure?
Usually I deploy .NET API to Azure App Service using Azure DevOps/GitHub Actions pipeline. Steps: build, run tests, publish artifact, deploy to App Service, use app settings for configuration, and monitor through Application Insights.
2. What are deployment slots?
Deployment slots are separate environments in App Service, like staging and production. We deploy to staging, validate, and then swap with production. It reduces downtime and risk.
3. How do you manage configuration in App Service?
Use App Service Application Settings for environment-specific config. Sensitive values should be stored in Key Vault and accessed through managed identity instead of hardcoding.
4. What is Managed Identity?
Managed Identity gives an Azure resource an automatically managed identity in Entra ID. It allows secure access to Key Vault, Storage or SQL without storing credentials in code.
5. How do you access Key Vault from an application?
Enable managed identity for the app, grant required Key Vault permissions/RBAC, then use Azure SDK to read secrets/certificates/keys. This avoids storing secrets in config files.
6. What are Azure Function triggers?
Triggers define how a function starts. Common triggers are HTTP trigger, Timer trigger, Queue trigger, Blob trigger, Event Grid trigger and Service Bus trigger.
7. Azure Function input/output bindings?
Bindings simplify connecting to services. Input binding reads data, output binding writes data. Example: HTTP request triggers function and output binding writes message to Queue Storage.
8. Consumption Plan vs Premium Plan for Functions?
Consumption plan is serverless and cost-effective for variable workloads but can have cold starts. Premium plan supports pre-warmed instances, VNet integration and better performance for production workloads.
9. What is Blob Storage used for?
Blob Storage is used for unstructured data like documents, images, logs, backups and report files. In reporting applications, generated reports can be stored as blobs and shared securely using SAS.
10. What is SAS token?
Shared Access Signature provides limited, time-bound access to Azure Storage resources. We can control permissions like read/write and expiry time.
11. What is Cosmos DB?
Azure Cosmos DB is a globally distributed NoSQL database with low latency, multiple APIs and flexible consistency models. It is useful when high scalability and global distribution are required.
12. What is partition key in Cosmos DB?
Partition key decides how data is distributed across physical partitions. A good partition key has high cardinality and evenly distributes workload to avoid hot partitions.
13. What are RUs in Cosmos DB?
RU means Request Unit. It represents the cost of database operations like read, write and query. We optimize queries and partitioning to reduce RU consumption.
14. Service Bus Queue vs Topic?
Queue supports one-to-one asynchronous messaging. Topic supports publish-subscribe where multiple subscribers can receive the same message based on subscriptions and filters.
15. Storage Queue vs Service Bus?
Storage Queue is simple queueing for basic workloads. Service Bus is enterprise messaging with features like topics, sessions, dead-letter queue, duplicate detection and transactions.
16. What is Dead Letter Queue?
Dead Letter Queue stores messages that cannot be delivered or processed after retries. It helps investigate failed messages without losing them.
17. Event Grid vs Event Hub?
Event Grid is for event routing/reactive event handling. Event Hub is for high-throughput streaming/telemetry ingestion like logs, IoT or clickstream data.
18. How do you secure APIs in Azure?
Use HTTPS, Entra ID/OAuth2/JWT authentication, API Management policies, rate limiting, Key Vault for secrets, managed identity for resource access and proper RBAC.
19. What is API Management?
API Management provides a gateway to publish, secure, monitor and manage APIs. It supports policies like authentication, rate limiting, caching, header transformation and versioning.
20. How do you monitor Azure applications?
Use Application Insights for request tracking, exceptions, dependency calls and performance metrics. Use Azure Monitor logs and alerts for proactive issue detection.
21. What is Application Insights dependency tracking?
It tracks external calls like SQL, HTTP, storage or service calls made by the application. It helps identify slow dependencies and failures.
22. How do you troubleshoot slow API response?
I check Application Insights for request duration, exceptions and dependency calls. Then I analyze SQL query time, external API latency, CPU/memory, logs and recent deployments. Based on root cause, I optimize query, add caching, scale app or fix code bottleneck.
23. What is retry pattern?
Retry pattern handles transient failures by retrying failed operations after short delays. It is useful for cloud services where temporary network/service issues can occur.
24. What is circuit breaker pattern?
Circuit breaker prevents repeated calls to a failing service. After failures cross threshold, circuit opens for some time and returns fallback response. It protects system stability.
25. How do you handle secrets in CI/CD?
Do not store secrets in repo. Store them in pipeline secret variables or Key Vault. Prefer managed identity/service connection with least privilege access.

4) Scenario-Based Answers

Scenario 1: Client says API is failing intermittently. What will you do?
I will first check monitoring dashboards and Application Insights for exception rate, failed dependency calls and response codes. Then I will check logs around the failure time, verify downstream services like SQL/Storage/API, and identify whether it is code issue, dependency issue or infrastructure issue. If needed, I will apply retry/circuit breaker and create alerts to catch it early next time.
Scenario 2: Report generation is slow. How will you improve?
I will analyze where time is spent: SQL query, API processing, file generation or storage. For SQL, I will check indexes, query plan and pagination. For application, I will use async processing/background jobs and caching where suitable. Large reports can be generated asynchronously and stored in Blob Storage with notification to user.
Scenario 3: How to design secure report download?
Store generated reports in private Blob Storage. User requests download through authenticated API. API validates user permission and generates short-lived read-only SAS URL or streams file. Secrets are kept in Key Vault and access is via managed identity.
Scenario 4: How to make API highly available?
Use App Service with multiple instances, autoscale rules, health checks, deployment slots, zone redundancy where applicable, database backup/replication, and monitoring alerts. For global users, use Front Door/Traffic Manager depending on requirement.
Scenario 5: How will you reduce Azure cost?
I will review utilization, right-size App Service plans/VMs, use autoscaling, choose correct storage tier, delete unused resources, set budgets/alerts, apply tags, and use reserved capacity for predictable workloads.
