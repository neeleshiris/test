1. Production API Debugging Scenarios

Q1. API issue आया है, कैसे पता करोगे problem कहां है?

ScenarioMust Know

I will not directly assume code issue. I will follow a layered approach:

  1. Confirm issue: endpoint, user impact, environment, exact time, status code.
  2. Client side: browser network tab / Postman request, payload, headers, token, response.
  3. API side: Application Insights failed requests, exceptions, traces, operation ID.
  4. Dependencies: SQL, external API, storage, service bus dependency failures.
  5. Configuration: app settings, connection strings, Key Vault references, environment variable.
  6. Deployment: recent release, slot swap, package mismatch, startup logs.
  7. Reproduce/debug: reproduce locally/staging; if still unclear use remote debugging carefully.
Interview answer: “I isolate the layer first. If request is not reaching API, I check network/CORS/auth. If reaching API and failing, I check App Insights exceptions and dependencies. If only Azure failing, I check configuration, Key Vault, deployment and App Service logs.”

Q2. API returns 500 Internal Server Error. What will you check?

  • Application Insights → Failures → Exceptions → stack trace.
  • Operation ID/correlation ID to trace complete request.
  • Dependency tab: SQL timeout, external API failure, storage failure.
  • Recent deployment/configuration changes.
  • App Service Log Stream for startup/runtime errors.

Root cause examples: null reference, bad config, SQL timeout, missing permission, Key Vault access denied.

Q3. API returns 401/403. How will you debug?

401 means authentication failed; 403 means authenticated but not authorized.

  • Check Authorization header and token expiry.
  • Validate issuer, audience, signing key, scopes/roles/claims.
  • Check API auth middleware order: Authentication before Authorization.
  • Check user role/claim mapping and policy configuration.

Q4. API returns 404 but code exists. What can be wrong?

  • Wrong route/controller/action attribute.
  • Wrong base URL or API version.
  • API Gateway/APIM routing issue.
  • Deployment did not include latest code.
  • App Service virtual directory/path issue.

Q5. API is working in Postman but not from browser/frontend.

  • Likely CORS issue, token issue, cookie/credential issue, or wrong frontend environment URL.
  • Check browser console and Network tab, especially preflight OPTIONS request.
  • Validate allowed origins, methods, headers, credentials and middleware order.

Q6. API is working locally but failing on Azure.

  • Azure App Settings missing/wrong.
  • Connection string points to wrong DB.
  • Key Vault permission/Managed Identity missing.
  • Firewall/private endpoint/VNet issue.
  • Different .NET runtime or environment variable.
  • Missing files after deployment.
Strong line: “If it fails only in Azure, I first suspect environment/configuration/permission/network before code.”

Q7. API is intermittently failing. How do you investigate?

Intermittent issues are often transient dependency failures, timeouts, deadlocks, throttling, race conditions, or instance-specific issues.

  • Check failure time pattern in App Insights.
  • Check if failures happen on one App Service instance only.
  • Check SQL deadlock/timeout, external API throttling.
  • Add correlation ID and structured logs.
  • Use retries with exponential backoff where safe.

Q8. API response is slow. How will you find bottleneck?

  • Application Insights Performance → slow endpoint.
  • Dependency duration → SQL/external API/storage.
  • Check N+1 queries, missing indexes, large payload, sync-over-async, thread pool starvation.
  • Check CPU/memory in App Service metrics.

Q9. API deployment successful but app not starting.

  • Check App Service Log Stream.
  • Check startup exception in Application Insights.
  • Check runtime stack and .NET version.
  • Check required app settings and connection strings.
  • Check web.config / process path for hosted app.

Q10. One user gets error but others do not. What will you check?

  • User-specific role/permission/claim.
  • User data causing edge case or null data.
  • Tenant/client-specific configuration.
  • Browser cache/token expiry.
  • Data volume for that user causing timeout.

2. Remote Debugging in Azure

Q11. What is remote debugging?

Remote debugging means attaching Visual Studio debugger to the process running on Azure App Service so we can hit breakpoints in deployed code. It is useful when issue cannot be reproduced locally and logs are not enough.

Caution: Avoid in production unless absolutely required. Prefer staging slot because remote debugging can slow down requests and expose runtime state.

Q12. How to do remote debugging for Azure App Service?

  1. Deploy same code/build symbols which you have locally.
  2. Azure Portal → App Service → Configuration → General Settings → enable Remote Debugging.
  3. Select correct Visual Studio version.
  4. Open same solution in Visual Studio.
  5. Debug → Attach to Process.
  6. Connection type: Microsoft Azure App Services.
  7. Select App Service and attach to w3wp.exe / dotnet.exe.
  8. Put breakpoint and hit API via Postman/browser.

Q13. Breakpoint is not hitting during remote debugging. Why?

  • Local code does not match deployed code.
  • Symbols/PDB not loaded.
  • Wrong process attached.
  • Endpoint not actually executing that code path.
  • Release optimization or old deployment running.
  • Multiple instances and request going to different instance.

Q14. Remote debugging vs logs: which one first?

First logs/telemetry. Remote debugging is last option when logs, App Insights, and reproducible test cases are not enough. For production, use App Insights, Snapshot Debugger, custom telemetry, or staging slot debugging where possible.

3. Application Insights / Logs / KQL

Q15. What exactly do you check in Application Insights?

  • Failures: failed requests/exceptions.
  • Performance: slow APIs and percentile latency.
  • Dependencies: SQL, HTTP, storage, Service Bus failures.
  • Transaction Search: trace complete request with operation ID.
  • Live Metrics: real-time requests/failures.

Q16. Give useful KQL queries for debugging.

// Failed requests in last 24 hours
requests
| where timestamp > ago(24h)
| where success == false
| project timestamp, name, url, resultCode, duration, operation_Id
| order by timestamp desc

// Exceptions with stack trace
exceptions
| where timestamp > ago(24h)
| project timestamp, type, message, operation_Id, outerMessage
| order by timestamp desc

// Slow dependencies
 dependencies
| where timestamp > ago(24h)
| order by duration desc
| project timestamp, type, target, name, duration, success, operation_Id

// Trace using correlation/operation id
union requests, traces, exceptions, dependencies
| where operation_Id == "PUT_OPERATION_ID_HERE"
| order by timestamp asc

Q17. Are all logs available in App Insights only?

No. App Insights is primary, but we also check App Service Log Stream, file system logs, Kudu, deployment logs, browser console/network tab, API gateway logs, and database logs depending on issue.

4. Browser Network Tab & Postman Debugging

Q18. What do you check in browser Network tab?

  • Request URL and method.
  • Status code: 400/401/403/404/500.
  • Request payload and query params.
  • Authorization header present or not.
  • Response body/error message.
  • CORS preflight OPTIONS call.
  • Timing waterfall: DNS, TLS, waiting, download.

Q19. How do you use Postman for debugging?

  • Reproduce request independent of frontend.
  • Set headers, token, payload manually.
  • Compare dev/test/prod responses.
  • Validate status code and response schema.
  • Use environment variables and collection tests.

Q20. 400 Bad Request कैसे debug करोगे?

Check model validation errors, required fields, enum value mismatch, wrong content-type, malformed JSON, date format issue, max request size, and API contract mismatch.

5. Azure Config, Deployment, App Service

Q21. Azure App Service में configuration कैसे manage करते हो?

Non-secret settings go in App Service Configuration. Secrets should go to Key Vault. Environment-specific settings should be separate for dev/test/prod. Avoid storing production secrets in appsettings.json.

Q22. Deployment slot क्यों use करते हैं?

For zero/low downtime deployment. Deploy to staging slot, verify health checks, warm up app, then swap to production. Rollback is faster by swapping back.

Q23. Recent deployment के बाद issue आया. What will you do?

  • Check release notes/changed files.
  • Check deployment logs and startup logs.
  • Compare app settings before/after.
  • Run smoke tests.
  • If high impact, rollback/swap slot first, then RCA.

6. ASP.NET Core Web API Deep Questions

Q24. Explain middleware pipeline order.

Exception handling should be early. Then HTTPS/static/routing/CORS/authentication/authorization/endpoints. Wrong order can cause CORS/auth failures.

app.UseExceptionHandler("/error");
app.UseHttpsRedirection();
app.UseRouting();
app.UseCors("Default");
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();

Q25. Scoped vs Transient vs Singleton?

Transient creates new instance every resolve. Scoped creates one per request. Singleton creates one for application lifetime. DbContext should generally be scoped. Do not inject scoped service directly into singleton.

Q26. How do you handle global exception?

Use exception middleware to log error and return consistent response with trace ID. Do not expose stack trace to client in production.

Q27. What is idempotency and why important?

Same request repeated should not create duplicate side effects. Important for retries, payment/order/report-generation APIs. Use idempotency key for POST operations where needed.

7. Logical / Coding Questions

Q28. Find first non-repeating character in a string.

public static char? FirstNonRepeating(string input)
{
    var dict = new Dictionary<char, int>();
    foreach (var ch in input)
        dict[ch] = dict.ContainsKey(ch) ? dict[ch] + 1 : 1;

    foreach (var ch in input)
        if (dict[ch] == 1) return ch;

    return null;
}

Complexity: O(n) time, O(k) space.

Q29. Reverse words in a sentence.

public static string ReverseWords(string sentence)
{
    return string.Join(" ", sentence.Split(' ', StringSplitOptions.RemoveEmptyEntries).Reverse());
}

Q30. Check if two strings are anagrams.

public static bool AreAnagrams(string a, string b)
{
    if (a.Length != b.Length) return false;
    return a.OrderBy(x => x).SequenceEqual(b.OrderBy(x => x));
}
For better performance, use frequency dictionary instead of sorting.

Q31. Find duplicate numbers in array.

public static IEnumerable<int> FindDuplicates(int[] nums)
{
    return nums.GroupBy(x => x)
               .Where(g => g.Count() > 1)
               .Select(g => g.Key);
}

Q32. Find missing number from 1 to n.

public static int MissingNumber(int[] nums, int n)
{
    int expected = n * (n + 1) / 2;
    int actual = nums.Sum();
    return expected - actual;
}

Q33. Check palindrome.

public static bool IsPalindrome(string input)
{
    int i = 0, j = input.Length - 1;
    while (i < j)
    {
        if (input[i] != input[j]) return false;
        i++; j--;
    }
    return true;
}

Q34. FizzBuzz.

for (int i = 1; i <= 100; i++)
{
    if (i % 15 == 0) Console.WriteLine("FizzBuzz");
    else if (i % 3 == 0) Console.WriteLine("Fizz");
    else if (i % 5 == 0) Console.WriteLine("Buzz");
    else Console.WriteLine(i);
}

Q35. Find second highest number.

public static int SecondHighest(int[] nums)
{
    return nums.Distinct().OrderByDescending(x => x).Skip(1).First();
}
Senior follow-up: handle empty/single-element array and avoid sorting for O(n).

Q36. Count occurrence of each word.

var result = sentence.Split(' ', StringSplitOptions.RemoveEmptyEntries)
                     .GroupBy(w => w.ToLower())
                     .ToDictionary(g => g.Key, g => g.Count());

8. LINQ / C# Practical Questions

Q37. Find employees with second highest salary.

var secondSalary = employees.Select(e => e.Salary)
                            .Distinct()
                            .OrderByDescending(s => s)
                            .Skip(1)
                            .FirstOrDefault();

var result = employees.Where(e => e.Salary == secondSalary);

Q38. Group employees by department.

var groups = employees.GroupBy(e => e.Department)
                      .Select(g => new { Department = g.Key, Count = g.Count() });

Q39. Difference between IEnumerable and IQueryable?

IEnumerable executes in memory. IQueryable builds expression tree and executes at data source like SQL. For database filtering, IQueryable is better because filtering happens in DB.

Q40. FirstOrDefault vs SingleOrDefault?

FirstOrDefault returns first matching record or default. SingleOrDefault expects zero or one record and throws exception if multiple records exist.

9. Async, Threading, Memory, Exceptions

Q41. Why use async/await in Web API?

For I/O-bound operations like DB/API calls, async releases thread while waiting, improves scalability, and allows server to handle more concurrent requests.

Q42. What is deadlock in async code?

Blocking async code using .Result or .Wait() can cause deadlock or thread starvation. Prefer await all the way.

Q43. Task vs Thread?

Thread is low-level execution unit. Task is higher-level abstraction representing asynchronous operation and may use thread pool.

Q44. How do you handle memory leak/high memory?

  • Check App Service memory metrics.
  • Look for static collections, unbounded cache, undisposed streams, large object allocations.
  • Use profiling/dumps in staging.
  • Dispose IDisposable and use streaming for large files.

10. SQL / EF Core Troubleshooting

Q45. SQL timeout in API. How will you debug?

  • Check App Insights dependency duration.
  • Check query execution plan and missing indexes.
  • Check blocking/deadlocks.
  • Check connection pool exhaustion.
  • Check if API is loading too much data without pagination.

Q46. What is N+1 query problem?

When one query loads parent records and then separate query runs for each child record. Fix using Include, projection, joins, or optimized query.

Q47. EF Core tracking vs AsNoTracking?

Tracking is useful when updating entities. AsNoTracking improves performance for read-only queries because EF does not track changes.

11. Microservices Scenario Questions

Q48. What is microservices?

Application is split into small independent services around business capabilities. Each service can be developed, deployed, scaled independently and communicates via REST/gRPC or messaging.

Q49. How to design Insurance Reporting Hub as microservices?

  • User Service
  • Report Service
  • Assignment Service
  • Notification Service
  • Audit Service

Use API Gateway/APIM, Service Bus for async notifications, SQL per service where possible, Application Insights for tracing, Key Vault for secrets.

Q50. Sync vs async communication?

Use REST/gRPC when immediate response is required. Use queue/topic when process can happen later and decoupling/reliability is more important.

Q51. How do you handle failures between microservices?

  • Timeouts
  • Retry with exponential backoff
  • Circuit breaker
  • Fallback response
  • Dead-letter queue for async messages
  • Correlation ID for tracing

Q52. What is Saga pattern?

Saga manages distributed transactions using sequence of local transactions and compensating actions. Used when multiple services update their own databases.

12. Service Bus / Queue Questions

Q53. Queue vs Topic?

Queue is one-to-one message processing. Topic is publish-subscribe where multiple subscribers can receive same event.

Q54. What is dead-letter queue?

Messages that cannot be processed after retries or validation failures move to dead-letter queue for investigation and reprocessing.

Q55. How do you avoid duplicate message processing?

Use idempotent consumers, message IDs, deduplication, and store processed message IDs when needed.

13. Security / JWT / Key Vault

Q56. Key Vault read/write कैसे करते हैं?

Create Key Vault, store secret, enable Managed Identity for app, grant permission/RBAC, use SecretClient with DefaultAzureCredential.

var client = new SecretClient(
    new Uri("https://your-vault.vault.azure.net/"),
    new DefaultAzureCredential());

var secret = await client.GetSecretAsync("DbConnection");
await client.SetSecretAsync("ApiKey", "value");

Q57. JWT token invalid issue कैसे debug करेंगे?

  • Check expiry.
  • Check issuer/audience.
  • Check signing key/certificate.
  • Check token sent in Authorization header.
  • Check scopes/roles/claims.

Q58. What if you have not worked on Key Vault?

“I have not implemented it directly in production, but I understand it is used for secret management. The app normally accesses secrets using Managed Identity and Azure SDK after proper permission.”

14. Performance & Scalability

Q59. How to improve API performance?

  • Async I/O
  • SQL optimization and indexes
  • Caching
  • Pagination
  • Compression
  • Reduce payload
  • Use App Insights to find bottleneck

Q60. Scale up vs scale out?

Scale up increases CPU/RAM of one instance. Scale out increases number of instances. For high traffic, scale out with autoscale is preferred.

Q61. How do you handle high traffic?

Use autoscale, caching, database optimization, queue-based background processing, CDN for static content, rate limiting, and proper monitoring.

15. Lead/Senior Behavioral

Q62. Production incident आया तो lead के तौर पर क्या करोगे?

Assess severity, communicate impact, assign owners, identify mitigation, rollback/hotfix if required, monitor recovery, then prepare RCA with preventive action.

Q63. If junior developer made production bug?

I will fix the incident first, then review the process. I focus on blameless RCA, test gaps, code review gaps, and mentoring.

Q64. If you don't know an answer?

“I have not worked directly on that in production, but I understand the concept. I would approach it by checking documentation, implementing a small POC, and validating with team standards.”
