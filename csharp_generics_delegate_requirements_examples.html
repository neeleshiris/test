C# Generics and Normal Delegate

Concept-first interview notes with real project requirements where delegate actually fits.

1. Generics in C# - Simple Concept

Interview Answer: Generics allow us to write reusable and type-safe code. We create a class, method, or interface with a placeholder type like T, and the actual type is provided at compile time.

Simple Explanation: Generic means type abhi fixed nahi hai. Jab use karenge tab decide karenge ki type int, string, Employee, Order ya koi aur hoga.

Why Generics?

  • Same logic multiple data types ke saath work kar sakti hai.
  • Compile-time type safety milti hai.
  • Casting avoid hoti hai.
  • Boxing/unboxing avoid hoti hai, so performance better hoti hai.
  • Duplicate code reduce hota hai.

2. Generic Class - Real-world Example: ApiResponse<T>

Real projects me APIs different data return karti hain. Kabhi Employee, kabhi Product, kabhi Order list, kabhi count. Agar har response ke liye alag class banayenge to duplicate code badh jayega.

public class ApiResponse<T>
{
    public bool Success { get; set; }
    public string Message { get; set; }
    public T Data { get; set; }
}
ApiResponse<Employee> employeeResponse = new ApiResponse<Employee>
{
    Success = true,
    Message = "Employee found",
    Data = new Employee { Id = 1, Name = "Neelesh" }
};

ApiResponse<List<Employee>> listResponse = new ApiResponse<List<Employee>>
{
    Success = true,
    Message = "Employees fetched",
    Data = new List<Employee>()
};

Interview Explanation: Same ApiResponse<T> class can return single employee, list of employees, product, order, or any other type. This is reusable and type-safe.

3. Normal Delegate - Core Concept

Interview Answer: A delegate in C# is a type-safe function pointer. It stores the reference of a method with matching signature and allows us to call that method later. Delegates are useful for callback, event handling, loose coupling, and runtime flexibility.

Simple Explanation: Delegate method ka reference store karta hai. Jaise variable value store karta hai, delegate method ka address/reference store karta hai.

Important line

Delegate ka best fit: Common logic fixed ho, lekin actual method/action fixed na ho. Caller ya runtime decide kare ki kaunsa method execute hoga.

4. Direct Call vs Delegate - Actual Difference

Direct Call

public void Execute()
{
    EmailService.SendEmail();
}

Yahaan method fixed hai. Is method ka kaam hamesha email bhejna hi hai.

Delegate

public delegate void JobDelegate();

public void Execute(JobDelegate job)
{
    job();
}

Yahaan method fixed nahi hai. Calling time decide hoga ki email chalega, SMS chalega, payment chalega ya file upload chalega.

Execute(EmailService.SendEmail);
Execute(SmsService.SendSms);
Execute(PaymentService.ProcessPayment);
Execute(FileService.UploadFile);

Interview line: Direct call is better when the method is fixed. Delegate is useful when the operation is dynamic and should be supplied by caller/runtime.

5. Real Project Requirement 1: Common Retry Executor

Requirement: Hume ek common retry mechanism banana hai jo kisi bhi failed operation ko 3 baar retry kare — email, SMS, payment, API call, file upload, kuch bhi.

Yahaan retry logic fixed hai:

Try karo
Fail ho to retry karo
Max 3 attempts

Lekin actual operation fixed nahi hai:

Kabhi EmailService.SendEmail
Kabhi SmsService.SendSms
Kabhi PaymentService.ProcessPayment
Kabhi FileService.UploadFile

Delegate Code

public delegate void JobDelegate();

public class RetryExecutor
{
    public void ExecuteWithRetry(JobDelegate job)
    {
        for (int attempt = 1; attempt <= 3; attempt++)
        {
            try
            {
                Console.WriteLine("Attempt: " + attempt);
                job(); // actual passed method is called here
                Console.WriteLine("Job completed successfully");
                break;
            }
            catch (Exception ex)
            {
                Console.WriteLine("Failed: " + ex.Message);

                if (attempt == 3)
                {
                    Console.WriteLine("All retry attempts failed");
                }
            }
        }
    }
}

Services

public class EmailService
{
    public static void SendEmail()
    {
        Console.WriteLine("Email sent");
    }
}

public class SmsService
{
    public static void SendSms()
    {
        Console.WriteLine("SMS sent");
    }
}

public class PaymentService
{
    public static void ProcessPayment()
    {
        Console.WriteLine("Payment processed");
    }
}

Calling Code

RetryExecutor retryExecutor = new RetryExecutor();

retryExecutor.ExecuteWithRetry(EmailService.SendEmail);
retryExecutor.ExecuteWithRetry(SmsService.SendSms);
retryExecutor.ExecuteWithRetry(PaymentService.ProcessPayment);

Why delegate fits here: RetryExecutor ko EmailService, SmsService, PaymentService ke baare me kuch nahi pata. Usko sirf ek job milti hai, aur wo us job ko retry ke saath execute karta hai. Isse class reusable aur loosely coupled ban jaati hai.

6. Real Project Requirement 2: File Upload ke baad action configurable ho

Requirement: Same FileUploader multiple modules me use hoga. HR module me upload ke baad email bhejna hai. Admin module me audit log likhna hai. Security module me virus scan karna hai.

File upload fixed hai, lekin upload ke baad kya hoga wo module decide karega.

HR Module       -> Send Email
Admin Module    -> Write Audit Log
Security Module -> Virus Scan

Delegate Code

public delegate void FileUploadedDelegate(string fileName);

public class FileUploader
{
    public FileUploadedDelegate FileUploaded;

    public void Upload(string fileName)
    {
        Console.WriteLine("File uploaded: " + fileName);
        FileUploaded?.Invoke(fileName);
    }
}

Services

public class EmailService
{
    public static void SendEmail(string fileName)
    {
        Console.WriteLine("Email sent for file: " + fileName);
    }
}

public class AuditService
{
    public static void WriteLog(string fileName)
    {
        Console.WriteLine("Audit log written for file: " + fileName);
    }
}

public class VirusScanner
{
    public static void Scan(string fileName)
    {
        Console.WriteLine("Virus scan completed for file: " + fileName);
    }
}

Calling Code - Different modules attach different actions

FileUploader uploader = new FileUploader();

// HR module requirement
uploader.FileUploaded += EmailService.SendEmail;

// Admin module requirement
uploader.FileUploaded += AuditService.WriteLog;

// Security module requirement
uploader.FileUploaded += VirusScanner.Scan;

uploader.Upload("resume.pdf");

Output

File uploaded: resume.pdf
Email sent for file: resume.pdf
Audit log written for file: resume.pdf
Virus scan completed for file: resume.pdf

Why delegate fits here: FileUploader class ka kaam sirf upload karna hai. Upload ke baad email, audit ya scan karna hai ya nahi, ye outside module decide karta hai. FileUploader ko direct dependency nahi hoti.

7. Real Project Requirement 3: Payment Success ke baad optional actions

Requirement: Payment success hone ke baad kuch clients ko email chahiye, kuch ko SMS chahiye, kuch ko reward points update chahiye, kuch ko audit log chahiye. Har client ka flow different ho sakta hai.

Client A: Payment -> Email -> Audit
Client B: Payment -> SMS -> Reward Points
Client C: Payment -> Email -> SMS -> Invoice

Delegate Code

public delegate void PaymentSuccessDelegate(string paymentId);

public class PaymentService
{
    public PaymentSuccessDelegate PaymentSuccess;

    public void ProcessPayment(string paymentId)
    {
        Console.WriteLine("Payment processed: " + paymentId);
        PaymentSuccess?.Invoke(paymentId);
    }
}

Subscriber Methods

public class NotificationService
{
    public static void SendEmail(string paymentId)
    {
        Console.WriteLine("Email sent for payment: " + paymentId);
    }

    public static void SendSms(string paymentId)
    {
        Console.WriteLine("SMS sent for payment: " + paymentId);
    }
}

public class RewardService
{
    public static void UpdateRewardPoints(string paymentId)
    {
        Console.WriteLine("Reward points updated for payment: " + paymentId);
    }
}

public class AuditService
{
    public static void WritePaymentAudit(string paymentId)
    {
        Console.WriteLine("Audit written for payment: " + paymentId);
    }
}

Calling Code

PaymentService paymentService = new PaymentService();

paymentService.PaymentSuccess += NotificationService.SendEmail;
paymentService.PaymentSuccess += NotificationService.SendSms;
paymentService.PaymentSuccess += RewardService.UpdateRewardPoints;
paymentService.PaymentSuccess += AuditService.WritePaymentAudit;

paymentService.ProcessPayment("PAY1001");

Why delegate fits here: PaymentService ka core kaam payment process karna hai. Payment ke baad kaunse optional actions chalenge, wo client/configuration/runtime decide kar sakta hai.

8. Real Project Requirement 4: Dynamic Validation / Filtering Rule

Requirement: Ek common filter banana hai jisme filtering process same ho, lekin condition caller decide kare.

Employee salary > 50000
Product price > 1000
Student marks > 60
Order amount > 10000

Filtering process fixed hai: list loop karo, condition true ho to result me add karo. But condition fixed nahi hai.

public delegate bool ConditionDelegate<T>(T item);

public class FilterService
{
    public List<T> Filter<T>(List<T> items, ConditionDelegate<T> condition)
    {
        List<T> result = new List<T>();

        foreach (T item in items)
        {
            if (condition(item))
            {
                result.Add(item);
            }
        }

        return result;
    }
}

Note: Modern C# me is type ke scenario ke liye mostly LINQ aur Func<T, bool> use hota hai. But conceptually ye delegate ka hi use case hai.

9. When NOT to Use Delegate

Delegate har jagah use nahi karna chahiye.

  • Agar method fixed hai aur hamesha same method call hona hai, direct call better hai.
  • Agar code simple hai, unnecessary delegate abstraction mat add karo.
  • Agar inter-service communication hai, jaise microservices, delegate nahi; message queue/API use karo.

Fixed method example

public void PlaceOrder()
{
    Console.WriteLine("Order placed");
    EmailService.SendEmail(); // fixed method, direct call is fine
}

10. Final Interview Answer

Delegate is useful when common logic is fixed but the actual operation is not fixed. For example, in a common retry executor, retry logic is fixed, but the operation can be email, SMS, payment, API call, or file upload. If we hardcode these methods inside the retry class, it becomes tightly coupled and we need to modify it for every new operation. With delegate, we pass the operation from outside, so the retry class remains reusable, loosely coupled, and extensible.

Similarly, in file upload or payment success scenarios, the core operation is fixed, but post-actions like email, SMS, audit, reward update, or virus scan may vary based on module, client, configuration, or runtime condition. In such cases, delegate fits well.

11. Quick Revision Lines

  • Direct call: Jab method fixed ho.
  • Delegate: Jab actual method dynamic ho.
  • Best delegate fit: Common logic fixed + actual action dynamic.
  • Examples: Retry executor, configurable file upload actions, payment success callbacks, dynamic filtering condition.
  • Microservices: Delegate nahi, message queue/API use hoti hai.
