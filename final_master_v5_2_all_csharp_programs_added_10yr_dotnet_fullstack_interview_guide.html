2. Angular Architecture - Detailed Expert Answer

Question: Explain Angular Architecture.
Definition: Angular is a TypeScript-based component-driven framework used to build scalable Single Page Applications. Its architecture is based on components, templates, services, dependency injection, routing, RxJS, modules/standalone components, guards, interceptors, and build optimization.

What exactly to explain

  • Component: UI building block with TypeScript class, HTML template, CSS/SCSS.
  • Template: View connected with component data using bindings.
  • Service: Reusable business logic and API communication.
  • Dependency Injection: Angular injects services instead of manual object creation.
  • Routing: Client-side navigation.
  • Guards: Route protection and navigation control.
  • Interceptors: Common HTTP handling like JWT, loader, logging, errors.
  • RxJS: Async stream handling.
  • Lazy Loading: Load feature only when required.
Speaking answer:
Angular follows component-based architecture. The UI is divided into reusable components. Each component has a TypeScript class for logic, an HTML template for view, and CSS/SCSS for styling. Common logic and API calls are kept in services. Angular uses dependency injection to provide services to components and other services.

Routing is used for navigation between views without full page reload. Guards protect routes based on authentication or authorization. Interceptors handle cross-cutting concerns such as adding JWT token, showing loader, logging requests, and global error handling. HttpClient communicates with backend APIs and returns Observables, which are handled using RxJS.

For enterprise applications, I prefer feature-based architecture with core folder for singleton services, shared folder for reusable UI components/pipes/directives, and feature folders for business modules. I use lazy loading, OnPush change detection, trackBy, and async pipe where suitable for performance.

Folder Structure Example

src/app
  core/
    services/
    guards/
    interceptors/
  shared/
    components/
    pipes/
    directives/
  features/
    users/
    orders/
    dashboard/
    reports/

Real project example

In one enterprise application, we used feature-based Angular structure. Core folder had AuthService, LoggerService, guards, and interceptors. Shared folder had reusable dropdowns, date pickers, pipes, and confirmation dialog components. Business features like Users, Orders, Dashboard, and Reports were separated. Reports module was lazy loaded because it was heavy and not required during initial application load.
Senior point: This structure reduces coupling, improves reusability, improves initial load time, and makes onboarding easier for new developers.

Angular SPA

Definition: SPA means browser loads one main HTML page initially and then views are updated dynamically on client side without full page reload.
Angular is called Single Page Application because initially browser loads index.html. After that, Angular Router changes views on client side. 10. Async/Await + Task + I/O-bound + CPU-bound Deep

Definition: Asynchronous programming allows long-running operations to complete without blocking current thread. In C#, async/await works with Task and Task<T>.
Core answer:
Async/await is mainly useful for I/O-bound work like database calls, API calls, file operations, and message queue operations. In ASP.NET Core, async improves scalability because while request waits for I/O, thread is released back to thread pool and can serve other requests.

CPU-bound: For long report calculation or file processing, I prefer background worker or queue-based processing rather than blocking API request.

Move Zeroes to End

Problem: Move all zeroes to end while maintaining order of non-zero elements. Do it in-place.
public static void MoveZeroes(int[] nums)
{
    int nonZeroIndex = 0;
    for (int i = 0; i < nums.Length; i++)
    {
        if (nums[i] != 0)
        {
            nums[nonZeroIndex++] = nums[i];
        }
    }
    while (nonZeroIndex < nums.Length)
    {
        nums[nonZeroIndex++] = 0;
    }
}
Dry run: Input [0,1,0,3,12]. Move non-zero values: [1,3,12,3,12]. Fill remaining with zero: [1,3,12,0,0]. Time O(n), Space O(1).

Q: Why not put business logic in controller?

Answer: Controller should handle HTTP concerns only. Business logic in controller makes code hard to test and maintain. Service layer keeps business rules reusable and testable.

Q: When will you use repository pattern with EF Core?

Answer: EF Core already provides repository/unit-of-work like behavior. I use repository or query service when I need abstraction, complex query isolation, or testability, but I avoid unnecessary generic repository if it adds no value.

Q: Why DTO instead of entity?

Answer: DTO prevents exposing database schema directly, controls response shape, avoids over-posting, improves security, and reduces payload.

Q: What is N+1 problem?

Answer: N+1 occurs when one query loads parent records and then separate query runs for each child. It causes performance issues. Fix using projection, Include carefully, or optimized query.

Q: When use AsNoTracking?

Answer: Use AsNoTracking for read-only queries because EF does not track changes and performance improves.

Q: When use Task.Run in ASP.NET Core?

Answer: Avoid Task.Run for normal I/O operations. Use it carefully for short CPU-bound work, but for long work prefer background worker or queue.

Q: Can async improve CPU-bound performance?

Answer: Async does not make CPU work faster. It improves scalability for I/O-bound operations. CPU-bound work needs parallel processing or background processing.

Q: What happens if RabbitMQ consumer crashes before ack?

Answer: If manual ack is used and consumer crashes before ack, message can be requeued depending on configuration. Repeated failures should go to retry/DLQ.

Q: Why idempotency in consumers?

Answer: Messages can be delivered more than once. Idempotent consumer prevents duplicate side effects like duplicate email or duplicate payment update.

Q: Why use Outbox?

Answer: Outbox prevents event loss between DB commit and message publish by storing event in same transaction and publishing later.

Q: How to handle distributed transaction?

Answer: Avoid distributed DB transaction where possible. Use Saga, eventual consistency, compensating actions, and reliable messaging.

Q: How to secure APIs?

Answer: Use HTTPS, JWT validation, role/claim authorization, input validation, CORS policy, rate limiting, secure secrets, and avoid exposing internal errors.

Q: What is difference between authentication and authorization?

Answer: Authentication verifies identity. Authorization verifies permission to access resource.

Q: What is OnPush?

Answer: OnPush change detection checks component mainly when input reference changes, event occurs, async pipe emits, or manual change detection happens. It improves performance.

Q: Observable vs Promise?

Answer: Promise returns single value and starts immediately. Observable can emit multiple values, is lazy, cancellable, and supports operators.

Q: switchMap vs mergeMap?

Answer: switchMap cancels previous inner observable and uses latest. mergeMap runs multiple inner observables in parallel.

Q: When use Redis?

Answer: Use Redis for distributed cache when multiple app instances need shared cache or when cache should survive beyond single process.

Q: How to debug slow API?

Answer: Check logs, response time, DB query time, external dependencies, CPU/memory, thread pool, recent deployment, and tracing.

Q: How to debug Angular slowness?

Answer: Check bundle size, API calls, rendering count, change detection, large DOM, images, and repeated subscriptions.

Q: How to handle production issue?

Answer: Use correlation ID, logs, metrics, recent deployment, dependency status, DB performance, reproduce, fix root cause, add monitoring/prevention.

Move Zeroes to End

Problem: Given an integer array, move all zeroes to end while maintaining relative order of non-zero elements. Do it in-place.

Approach

  • Use pointer nonZeroIndex.
  • Move non-zero values to front in same order.
  • Fill remaining positions with zero.
  • Time O(n), Space O(1).
public static void MoveZeroes(int[] nums)
{
    int nonZeroIndex = 0;

    for (int i = 0; i < nums.Length; i++)
    {
        if (nums[i] != 0)
        {
            nums[nonZeroIndex++] = nums[i];
        }
    }

    while (nonZeroIndex < nums.Length)
    {
        nums[nonZeroIndex++] = 0;
    }
}

1. Reverse String

Explanation: We convert the string into a character array and swap first character with last, second with second-last, and continue until the middle. This is easy to explain and easy to write in interview.
Steps:

  • Use for loop till half length.
  • Swap chars[i] with chars[length - 1 - i].
  • Create new string from char array.
Example: Input: hello -> Output: olleh
using System;

{
    static void Main()
    {
        string input = "hello";
        char[] chars = input.ToCharArray();

        for (int i = 0; i < chars.Length / 2; i++)
        {
            char temp = chars[i];
            chars[i] = chars[chars.Length - 1 - i];
            chars[chars.Length - 1 - i] = temp;
        }

    }
}

8. Merge Two Sorted Arrays

Explanation: Because both arrays are already sorted, we use two pointers and pick the smaller element each time. This is the standard merge step of merge sort.
Steps:
  • Create result array of size arr1.Length + arr2.Length.
  • Use i for first array, j for second array, k for result.
  • Compare arr1[i] and arr2[j].
  • Copy remaining elements after one array ends.
Example: Input: [1,3,5] and [2,4,6] -> Output: [1,2,3,4,5,6]
using System;

class Program
{
    static void Main()
    {
        int[] first = { 1, 3, 5 };
        int[] second = { 2, 4, 6 };
        int[] result = new int[first.Length + second.Length];

        int i = 0, j = 0, k = 0;

        while (i < first.Length && j < second.Length)
        {
            if (first[i] <= second[j])
            {
                result[k] = first[i];
                i++;
            }
            else
            {
                result[k] = second[j];
                j++;
            }
            k++;
        }

        while (i < first.Length)
        {
            result[k] = first[i];
            i++;
            k++;
        }

        while (j < second.Length)
        {
            result[k] = second[j];
            j++;
            k++;
        }

        Console.WriteLine(string.Join(", ", result));
    }
}
Complexity: Time: O(n + m), Space: O(n + m).
How to speak: Interview line: Since arrays are sorted, two-pointer merge is more efficient than combining and sorting again.

9. Valid Parentheses

Explanation: We use stack. Opening brackets are pushed. For closing bracket, top of stack must be matching opening bracket.
Steps:
  • Create stack.
  • Push opening brackets.
  • For closing bracket, check stack is not empty.
  • Pop and compare with expected opening bracket.
  • At end stack should be empty.
Example: Input: {[()]} -> Output: True
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        string input = "{[()]}";
        Stack<char> stack = new Stack<char>();
        bool isValid = true;

        for (int i = 0; i < input.Length; i++)
        {
            char ch = input[i];

            if (ch == '(' || ch == '{' || ch == '[')
            {
                stack.Push(ch);
            }
            else
            {
                if (stack.Count == 0)
                {
                    isValid = false;
                    break;
                }

                char top = stack.Pop();

                if ((ch == ')' && top != '(') ||
                    (ch == '}' && top != '{') ||
                    (ch == ']' && top != '['))
                {
                    isValid = false;
                    break;
                }
            }
        }

        if (stack.Count != 0)
        {
            isValid = false;
        }

        Console.WriteLine(isValid);
    }
}
Complexity: Time: O(n), Space: O(n).
How to speak: Interview line: Stack works because the last opened bracket must be closed first.
