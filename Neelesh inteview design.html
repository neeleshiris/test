2. Reporting Hub Project Explanation

Q: Explain your project in detail.

I worked on a Reporting Hub application. It is a centralized platform used to manage and provide access to different reports for different users in an organization.

The important point is that Reporting Hub does not generate reports by itself. It works as a secure report access management system. Reports are created in external tools like Power BI and Tableau, and our application stores report metadata, report URLs, user mappings, role mappings, and access configuration.

We have two types of users in the system. Internal users are authenticated using Azure Active Directory, and external users are authenticated using Azure B2C. For authentication and token handling, we used MSAL library.

Admin users can create report entries in the application, configure report details, and assign reports to users or roles. When a user logs in, the system checks the user identity, role, and assigned reports, and then displays only those reports which the user is authorized to access.

For external users, we also integrated embedded Power BI reports with Row Level Security, so users can see only their permitted data inside the report. We also support Tableau report URLs depending on report configuration.

The frontend is built using AngularJS, backend APIs are built using .NET Core, database is Azure SQL Database, application is hosted on Azure App Service, and monitoring is done through Application Insights.

Q: What was your role in the project?

My role was as a .NET Full Stack Developer. I worked on frontend, backend, authentication, authorization, API development, database interaction, Azure deployment, monitoring, and production issue fixing.

On the frontend side, I created AngularJS components, services, HTTP interceptors, and auth guards. On the backend side, I developed .NET Core APIs and implemented role-based access control.

I also worked on Azure App Service deployment, Application Insights monitoring, and CI/CD related activities like pull requests, build pipelines, and deployment to Azure App Service.

Q: What is the business purpose of Reporting Hub?

The business purpose is to provide a single secure platform where users can access all organization reports based on their permissions.

Instead of sharing Power BI or Tableau links manually, admin can manage report access from one system. This improves security, user management, auditability, and maintainability.

Q: What are the main modules?

  • Authentication module: Azure AD for internal users and Azure B2C for external users.
  • Authorization module: Role-based and user-based report access.
  • Admin module: Admin can create report entries and assign reports.
  • Report listing module: Users can see only assigned reports.
  • Report viewer module: Displays Power BI or Tableau reports.
  • Monitoring module: Application Insights for logs, exceptions, and performance tracking.

Q: What was your biggest challenge in this project?

One major challenge was implementing role-based authorization because the access token from Azure AD and Azure B2C did not contain the role claim required by our application.

To solve this, after successful authentication, I fetched the user role and permissions from Azure SQL Database based on the logged-in user. Then I added that role information into the application claims and used those claims for API-level authorization and UI-level access control.

This solution helped us ensure that each user can access only assigned reports and authorized features.

3. Architecture and Flow

Q: Explain the architecture of your application.

The application follows a layered architecture. The frontend is developed in AngularJS. It communicates with .NET Core Web APIs.

The backend APIs handle business logic, authentication validation, authorization, report access logic, and database operations.

Azure SQL Database stores report metadata, user mapping, role mapping, and configuration data. Azure App Service hosts the application, and Application Insights is used for logging and monitoring.

Q: Explain login to report access flow.

  1. User opens Reporting Hub.
  2. User logs in using Azure AD for internal users or Azure B2C for external users.
  3. MSAL receives token after successful login.
  4. Angular HTTP interceptor attaches token to API requests.
  5. .NET Core API validates token.
  6. API fetches role and report mapping from Azure SQL Database.
  7. Only authorized reports are returned to UI.
  8. User opens Power BI or Tableau report based on access.
  9. Application Insights captures logs, exceptions, and performance data.

Q: What work did you do in AngularJS?

Q: What is a component?

A component is responsible for a specific UI part of the application. It contains view, data binding, and logic for that part.

In my project, examples of components are report list component, report viewer component, admin report management component, and user mapping component.

Q: What is a service in Angular?

A service is used to keep reusable logic outside components. It is commonly used for API calls, shared data, authentication logic, and utility methods.

In my project, I used services to call .NET Core APIs for reports, users, roles, and authentication-related operations.

Q: What is HTTP interceptor and why did you use it?

HTTP interceptor intercepts outgoing requests and incoming responses. I used it to add bearer token in the request header for every API call.

This avoids writing token logic in every service method. I also used it for global error handling, like handling 401 unauthorized, 403 forbidden, and common API errors. 
Authorization: Bearer <access_token>

Q: What is Auth Guard?

Auth Guard is used to protect application routes. Before opening a route, it checks whether the user is authenticated and authorized.

If the user is not logged in, it redirects to login. If the user does not have permission, it redirects to unauthorized page or dashboard.

Q: How did you manage token in Angular?

We used MSAL library for authentication. After login, MSAL provides access token. Angular service or interceptor retrieves the token and attaches it to API requests.

Token expiration and refresh are handled through MSAL flow.

Q: How did you show only assigned reports in UI?

After login, Angular calls backend API to get the list of reports assigned to the user.

Backend checks user identity, roles, and report mapping from database, and returns only authorized reports. Angular displays only those reports in the report list component.

5. .NET Core / Web API Questions

Q: What work did you do in .NET Core?

I developed .NET Core Web APIs for report management, user-role mapping, report assignment, authentication support, and authorization checks.

I used dependency injection, service layer, repository or data access layer, middleware, configuration management, logging, and exception handling.

Q: Explain Dependency Injection.

Dependency Injection is a design pattern where dependencies are provided from outside instead of creating them inside the class.

It improves testability, loose coupling, and maintainability. In .NET Core, services are registered in the DI container and injected through constructors.

Q: Explain Singleton, Scoped, and Transient.

  • Singleton: One instance for the entire application lifetime.
  • Scoped: One instance per HTTP request. Commonly used for database context and request-specific services.
  • Transient: New instance every time it is requested. Used for lightweight stateless services.

Q: What is middleware in .NET Core?

Middleware is a component in the HTTP request pipeline.

Each middleware can process the request, pass it to next middleware, and process the response. Examples are authentication, authorization, exception handling, routing, CORS, and logging middleware.

Q: Authentication vs Authorization?

Authentication means verifying who the user is.

Authorization means verifying what the user is allowed to access.

In my project, Azure AD/B2C handles authentication, and our application role mapping handles authorization.

Q: IEnumerable vs IQueryable?

IEnumerable works mainly with in-memory collections.

IQueryable builds database queries and executes them at database level. For database filtering, IQueryable is better because it can apply filters in SQL before data comes to application memory.

Q: How do you handle exceptions in API?

I prefer centralized exception handling using middleware or filters.

It logs exceptions, returns proper HTTP status codes, and avoids exposing sensitive technical details to users. We can log exceptions into Application Insights for analysis.

Q: How do you improve API performance?

I improve API performance by optimizing SQL queries, using proper indexes, avoiding unnecessary data loading, using async/await for I/O operations, implementing caching where needed, using pagination for large data, and monitoring slow dependencies using Application Insights.

We implemented authentication using Azure AD for internal users and Azure B2C for external users.

On the frontend, we used MSAL library to handle login, token acquisition, and token management. The access token is sent to backend APIs in the Authorization header.

Azure AD is suitable for internal organization users because they already exist in the company's tenant.

Azure B2C is suitable for external users because it supports customer or external identity management, sign-up/sign-in policies, and external identity providers.

Q: What is MSAL?

MSAL means Microsoft Authentication Library. It is used to authenticate users and acquire tokens from Azure AD or Azure B2C.

In our application, MSAL helped with login, token acquisition, token refresh, and user session management.

Q: What issue did you face with role claim?

The token did not contain the role claim required for our application authorization.

Because of that, we could authenticate the user, but we could not directly decide application permissions from token.

I solved it by fetching roles and permissions from database after login and adding them into application claims. Then I used those claims for route access, API authorization, and report visibility.

Q: How did you secure APIs?

APIs are secured by validating JWT access tokens, using HTTPS, applying authorization checks, validating inputs, avoiding sensitive data exposure, handling CORS carefully, and logging suspicious or failed requests where required.

  • App Service: Best for normal web applications and APIs where we do not want to manage infrastructure.
  • AKS: Best for containerized microservices where we need orchestration, scaling, and more control.
  • Azure Functions: Best for event-driven small tasks like scheduled jobs, queue triggers, file processing, or lightweight background work.

Q: Why would you not choose AKS?

I would not choose AKS if the application is not complex enough to justify Kubernetes operational overhead.

AKS needs containerization, cluster management, monitoring, networking, scaling configuration, and DevOps maturity. For a normal web application, Azure App Service is simpler, cost-effective, and easier to maintain.

10. Azure SQL and Database Questions

Q: What data did you store in Azure SQL?

We stored user information, roles, report metadata, report URLs, report assignment, user-role mapping, and configuration data in Azure SQL Database.

Q: How do you optimize SQL queries?

I optimize SQL queries by creating proper indexes, selecting only required columns, avoiding unnecessary joins, using pagination, checking execution plans, avoiding N+1 queries, and moving filtering to database level instead of application memory.

Q: Types of joins?

Inner join returns matching records from both tables.

Left join returns all records from left table and matching records from right table.

Right join returns all records from right table and matching from left.

Full join returns records from both sides whether matching or not.

Q: What is index?

Index improves data retrieval performance by allowing database to find rows faster.

However, too many indexes can slow down insert/update/delete operations, so indexes should be created based on query patterns.

13. Security and Penetration Testing

Q: You mentioned penetration testing. What issues can come and how did you fix them?

In penetration testing, common findings can be missing security headers, weak CORS configuration, sensitive information exposure, improper authorization, token handling issues, SQL injection risk, XSS risk, and insecure error messages.

We fixed issues by validating inputs, improving authorization checks, hiding technical error details, using HTTPS, applying secure headers, restricting CORS, and ensuring APIs return only authorized data.

Q: How do you prevent SQL injection?

Use parameterized queries or ORM with parameters, avoid dynamic SQL string concatenation, validate inputs, and apply least privilege access to database users.

Q: How do you prevent XSS?

Encode output, validate input, avoid rendering raw HTML from user input, use safe binding practices, and apply content security headers where possible.

Q: What is broken access control?

Broken access control happens when a user can access data or functionality which they are not allowed to access.

In Reporting Hub, we prevent this by checking user roles and report assignments at API level, not only at UI level.

15. Scalable System Design

Q: How would you design a highly scalable reporting system?

I would design it with a clear separation between frontend, backend APIs, database, authentication provider, and external report providers.

The frontend would call backend APIs. Backend would handle authorization, report metadata, and access rules. Reports would come from Power BI or Tableau.

User authentication would be handled by Azure AD or B2C. Report access mapping would be stored in database.

For scalability, I would use Azure App Service scale-out, optimized SQL queries, caching for frequently used metadata, and Application Insights for monitoring.

Q: How would you handle 10,000 users or high traffic?

For 10,000 users, I would consider load balancing, horizontal scaling, distributed caching like Redis, database read replicas or scaling, API pagination, async processing for heavy tasks, CDN for static assets, queue-based background processing, rate limiting, and strong monitoring.

If the domain grows large, we can split modules into microservices, but I would not start with microservices unless there is a clear need.

Q: How do you design failure handling?

Use proper exception handling, retry for transient failures, timeout configuration, circuit breaker pattern for external dependencies, logging, alerts, graceful error messages, and fallback behavior where possible.

Q: What if external report provider is down?

The application should show a user-friendly message, log the failure, avoid crashing the whole app, and retry only where appropriate.

Monitoring alerts should notify the support team. If possible, cache report metadata but not sensitive report data unless allowed.

16. Microservices, CQRS, RabbitMQ - Basic Safe Answers

Important: Since you did not work deeply on microservices, CQRS, and RabbitMQ, answer honestly but confidently. Do not claim deep production experience.

Q: Have you worked on microservices?

I have not worked deeply on a full microservices-based production system. My main production experience is with .NET Core APIs and Azure App Service.

However, I understand the basic concepts of microservices, like splitting application into small independent services, independent deployment, service-to-service communication, and scaling services independently.

Q: What is microservices architecture?

Microservices architecture splits a large application into small independent services.

Each service owns a specific business capability, can be developed and deployed independently, and may have its own database.

It improves scalability and independent deployment but increases complexity in communication, monitoring, and data consistency.

Q: What is CQRS?

CQRS means Command Query Responsibility Segregation.

It separates write operations from read operations. Commands are used to change data, and queries are used to read data.

It is useful when read and write workloads are different or need separate optimization.

Q: What is RabbitMQ?

RabbitMQ is a message broker used for asynchronous communication.

One service publishes a message to a queue, and another service consumes it. It helps decouple services and handle background processing or event-driven workflows.

Q: Sync vs Async communication?

Synchronous communication means caller waits for immediate response, like REST API call.

Asynchronous communication means caller sends message and does not wait for immediate completion, like using queue or message broker. Async is better for long-running or decoupled processes.

17. Coding and Logic Questions

Q: Move zeros to right in array.

void MoveZerosToRight(int[] arr)
{
    int index = 0;

    for (int i = 0; i < arr.Length; i++)
    {
        if (arr[i] != 0)
        {
            arr[index++] = arr[i];
        }
    }

    while (index < arr.Length)
    {
        arr[index++] = 0;
    }
}

Q: Move zeros to left in array.

void MoveZerosToLeft(int[] arr)
{
    int index = arr.Length - 1;

    for (int i = arr.Length - 1; i >= 0; i--)
    {
        if (arr[i] != 0)
        {
            arr[index--] = arr[i];
        }
    }

    while (index >= 0)
    {
        arr[index--] = 0;
    }
}

Q: Bubble sort and why two loops?

Bubble sort uses two loops because the inner loop compares adjacent elements and moves the largest element to the end in each pass.

The outer loop repeats this process until all elements are sorted. After every outer pass, one element reaches its correct position. 
void BubbleSort(int[] arr)
{
    for (int i = 0; i < arr.Length - 1; i++)
    {
        for (int j = 0; j < arr.Length - i - 1; j++)
        {
            if (arr[j] > arr[j + 1])
            {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}

Q: Reverse words without Array.Reverse.

using System.Text;

string ReverseWords(string input)
{
    string[] words = input.Split(' ');
    StringBuilder result = new StringBuilder();

    for (int i = words.Length - 1; i >= 0; i--)
    {
        result.Append(words[i]);

        if (i != 0)
        {
            result.Append(" ");
        }
    }

    return result.ToString();
}
