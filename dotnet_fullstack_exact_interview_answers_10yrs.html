2. .NET Theoretical Questions - Exact Answers

Q1. Explain Dependency Injection.

Exact Answer:
Dependency Injection is a design pattern used to achieve loose coupling between classes. Instead of a class creating its dependency using the new keyword, the dependency is injected from outside, mostly through constructor injection. ASP.NET Core has a built-in dependency injection container where we register services with lifetimes like Transient, Scoped, and Singleton.

In my projects, I use DI to inject services, repositories, DbContext, loggers, configuration, and HTTP clients. It makes the code testable, maintainable, and easy to change because classes depend on abstractions instead of concrete implementations.
builder.Services.AddScoped<IPayrollService, PayrollService>();

public class PayrollController : ControllerBase
{
    private readonly IPayrollService _payrollService;

    public PayrollController(IPayrollService payrollService)
    {
        _payrollService = payrollService;
    }
}

Q2. What are SOLID principles? Explain L.

Exact Answer:
SOLID is a set of five object-oriented design principles used to write maintainable, scalable, and testable code. S is Single Responsibility, O is Open/Closed, L is Liskov Substitution, I is Interface Segregation, and D is Dependency Inversion.

Liskov Substitution Principle means a child class should be replaceable with its parent class without breaking application behavior. If derived class changes expected behavior or throws unsupported exceptions for base behavior, then it violates LSP.

For example, if Bird has Fly method and Ostrich inherits Bird but cannot fly, then it is a wrong design. Better design is to separate flying behavior into an interface.
public interface IBird { }
public interface IFlyingBird : IBird
{
    void Fly();
}

public class Sparrow : IFlyingBird
{
    public void Fly() { }
}

public class Ostrich : IBird
{
    // Ostrich is a bird but not a flying bird
}

Q3. Explain Garbage Collector.

Exact Answer:
Garbage Collector is part of .NET CLR and it automatically manages managed memory. When an object is no longer reachable from application roots, GC marks it as eligible for collection and frees memory. GC works with generations: Gen 0 for short-lived objects, Gen 1 as a buffer, and Gen 2 for long-lived objects. Large objects are stored in Large Object Heap.

Normally we should not force garbage collection because GC is optimized. Technically we can call GC.Collect(), but in real production applications it should be avoided unless there is a very specific scenario. For unmanaged resources like file handles, streams, database connections, and native resources, we use IDisposable and using.
using var stream = new FileStream(filePath, FileMode.Open);

In microservices, correlation id is very important because it helps trace one request across multiple services.

In production, logs are usually pushed to centralized tools like Application Insights, ELK, Splunk, Seq, Azure Monitor, or GCP Cloud Logging.

Q5. Explain Service Lifecycle in .NET Core: Transient, Scoped, Singleton.

Exact Answer:
In ASP.NET Core DI, service lifetime defines how long an object instance will live.

Transient creates a new instance every time it is requested. I use it for lightweight stateless services like validators, mappers, or formatters.

Scoped creates one instance per HTTP request. I use it for DbContext, repositories, unit of work, and request-specific services.

Singleton creates one instance for the entire application lifetime. I use it for thread-safe stateless services like cache provider, configuration reader, or common utility service.

One important rule is that we should not inject scoped services directly into singleton services because it can create captive dependency issues.
builder.Services.AddTransient<IValidator, PayrollValidator>();
builder.Services.AddScoped<IPayrollRepository, PayrollRepository>();
builder.Services.AddSingleton<IAppCache, AppCache>();

Q9. How do you resolve multiple dependencies in .NET Core?

Exact Answer:
If multiple implementations exist for the same interface, I resolve them using IEnumerable<T>, factory pattern, or keyed services depending on the .NET version and requirement. In real projects, factory pattern is very useful when implementation is selected based on runtime condition like email, SMS, or push notification.
public interface INotificationService
{
    string Type { get; }
    void Send(string message);
}

public class NotificationFactory
{
    private readonly IEnumerable<INotificationService> _services;

    public NotificationFactory(IEnumerable<INotificationService> services)
    {
        _services = services;
    }

    public INotificationService Get(string type)
    {
        return _services.First(x => x.Type == type);
    }
}

Q10. Difference between var and dynamic.

Exact Answer:
var is compile-time type inference. The compiler decides the type at compile time and after assignment the type cannot change. dynamic is resolved at runtime and type checking happens at runtime. If a member does not exist, dynamic errors come at runtime, while var errors are caught at compile time.

I use var for readability, especially with LINQ or obvious types. I avoid dynamic unless required for reflection, COM, or dynamic JSON-like scenarios.
var x = 10;      // compile-time int
// x = "test";  // compile error

dynamic y = 10;
y = "test";     // allowed at runtime

3. .NET Practical / Debugging Questions

Q. Session variable sometimes showing and sometimes not on UI, session not expired. How will you debug?

Exact Answer:
I will debug it step by step instead of assuming session timeout. First, I will reproduce the issue and check whether the session value is set correctly and read correctly. I will log session id, correlation id, user id, server instance, and the exact point where session is set and retrieved.

If application is running on multiple servers behind load balancer, I will check whether session is in-memory. In-memory session can fail if next request goes to another server. In that case, solution is sticky session or distributed session using Redis/SQL Server.

I will also check browser cookies, SameSite/Secure settings, domain/path issues, AJAX race condition, middleware order, and whether any code path is clearing or overwriting the session. On UI side, I will check network tab to confirm API call sequence and whether UI is reading data before session set API completes.
app.UseRouting();
app.UseSession();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();

Q. For a given data query, how will you optimize it? Have you used any tool?

Exact Answer:
First, I identify the slow query using application logs, APM, SQL Profiler, Extended Events, Query Store, or EF Core logging. Then I check the actual execution plan to find table scans, missing indexes, expensive joins, key lookups, blocking, or parameter sniffing issues.

From code side, I make sure filtering happens before ToList, only required columns are selected using projection, AsNoTracking is used for read-only queries, pagination is applied, and unnecessary Include or N+1 queries are removed. From database side, I verify proper indexes on WHERE, JOIN, ORDER BY columns and update statistics if required.
var data = await _db.Payrolls
    .AsNoTracking()
    .Where(x => x.EmployeeId == employeeId && x.Year == year)
    .Select(x => new PayrollDto
    {
        EmployeeId = x.EmployeeId,
        NetSalary = x.NetSalary
    })
    .ToListAsync();

Q. Output question: call by value and call by reference.

Exact Answer:
In C#, parameters are passed by value by default. For value types, a copy of the value is passed, so changes inside method do not affect original variable. If we use ref, then reference to the same variable is passed, so changes inside method affect original value.
static void ChangeValue(int x)
{
    x = 20;
}

static void ChangeRef(ref int x)
{
    x = 20;
}

int a = 10;
ChangeValue(a);
Console.WriteLine(a); // 10

ChangeRef(ref a);
Console.WriteLine(a); // 20

Q. Is function overloading possible in JavaScript and TypeScript?

Exact Answer:
JavaScript does not support true function overloading. If we define multiple functions with the same name, the last one overrides the previous one. We handle it using optional parameters, rest parameters, or type checks.

TypeScript supports overload signatures, but internally there is only one implementation method. So TypeScript gives compile-time overloading support, but JavaScript runtime still has a single function implementation.
function format(value: number): string;
function format(value: string): string;
function format(value: number | string): string {
  return value.toString();
}

Q. Observable and how it will be cancellable?

Exact Answer:
Observable represents an asynchronous data stream. In Angular, HTTP calls return Observables. We can cancel an Observable by unsubscribing. For search scenarios, I use switchMap because it cancels the previous pending request when a new value comes. For component cleanup, I use takeUntil or takeUntilDestroyed to avoid memory leaks.

If we cancel the observable from UI, it cancels the client-side subscription/request. Whether backend processing stops depends on whether the request already reached the server and whether backend supports cancellation token. For important operations, backend should be idempotent and transaction-safe.
this.searchText$.pipe(
  debounceTime(300),
  distinctUntilChanged(),
  switchMap(text => this.api.search(text))
).subscribe();

Q. What are Signals in Angular?

6. Design Principles & Patterns

Q. What are design principles? Give real-world example.

Exact Answer:
Design principles are guidelines that help us write clean, maintainable, scalable, and testable code. In my project, I applied separation of concerns by keeping controller, service, repository, validator, and DTO responsibilities separate. Controller only handles HTTP request/response, service handles business rules, repository handles data access, and validator handles input validation. This makes code easy to change and easy to unit test.

Q. What is Repository Pattern and drawbacks?

Exact Answer:
Repository pattern abstracts data access logic from business logic. Service layer calls repository methods instead of directly writing database queries everywhere. It improves testability and keeps business logic clean.

The drawback is that with EF Core, DbContext already behaves like repository and unit of work. If we create too many generic repositories, it may become unnecessary abstraction and hide LINQ capabilities. So I use repository pattern only when it adds value, especially for complex domain data access or when we want to isolate persistence logic.

Q. What is Event-Driven Pattern?

Exact Answer:
Event-driven pattern means services communicate by publishing and consuming events. For example, when payroll is processed, Payroll service publishes PayrollProcessed event. Notification service consumes it and sends email, Audit service consumes it and stores audit logs. This reduces tight coupling and improves scalability because services do not need to call each other directly for every action.

Q. What is CQRS pattern?

Exact Answer:
CQRS means Command Query Responsibility Segregation. It separates write operations from read operations. Commands are used for create/update/delete where business validation and consistency are important. Queries are used only for reading data and can be optimized separately.

CQRS improves performance because read models can be denormalized, cached, indexed differently, or scaled independently. I use CQRS when read and write requirements are complex or when performance/scalability demands are high.

7. Architecture, HLD, LLD, Testing

Q. What is HLD and LLD?

Exact Answer:
HLD means High Level Design. It explains overall system architecture such as modules, services, database, external integrations, security, deployment, and data flow. LLD means Low Level Design. It explains implementation-level details such as classes, interfaces, methods, API contracts, database tables, validations, sequence flow, and error handling.

In short, HLD answers how the system is structured, and LLD answers how each component will be implemented.

Q. What is unit testing and how have you implemented it?

Exact Answer:
Unit testing is testing a small unit of code in isolation, usually a method or service. I have implemented unit tests using xUnit/NUnit/MSTest and mocking frameworks like Moq. I mostly test service layer business logic, validations, edge cases, and exception scenarios. Dependencies like repository or external API are mocked so that test focuses only on the unit being tested.

Q. What is mocking?

Exact Answer:
Mocking means creating fake implementations of dependencies for unit testing. For example, instead of calling real database repository, we mock repository and return predefined data. This makes tests faster, isolated, predictable, and independent of external systems.
var repo = new Mock<IPayrollRepository>();
repo.Setup(x => x.GetAsync(1)).ReturnsAsync(new Payroll());

8. C# and .NET Core Concepts

Q. Why are you using .NET Core? Benefits over .NET Framework?

Exact Answer:
.NET Core is cross-platform, high-performance, cloud-friendly, open-source, and suitable for modern applications and microservices. It has built-in dependency injection, logging, configuration, middleware pipeline, side-by-side versioning, and better support for Docker/Kubernetes. .NET Framework is mostly Windows-only and mainly used for legacy applications, while .NET Core/.NET is preferred for modern development.

Q. What is unmanaged code and how do you manage it?

Exact Answer:
Unmanaged code is code or resources not directly managed by CLR, like file handles, database connections, sockets, COM objects, or native DLL resources. In .NET, I manage unmanaged resources using IDisposable, using statement, SafeHandle, and proper Dispose pattern. For normal managed objects, GC handles memory automatically.

Q. What are Generics?

Exact Answer:
Generics allow us to write reusable and type-safe code. Instead of writing separate classes or methods for every type, we use type parameter like T. Generics improve compile-time safety and avoid boxing/unboxing for value types.
public class ApiResponse<T>
{
    public bool Success { get; set; }
    public T Data { get; set; }
}

Q. What are Func<> and Predicate<>?

Exact Answer:
Func and Predicate are built-in delegates. Func takes input parameters and returns a value. Predicate takes one input parameter and returns boolean. Predicate is mainly used for conditions.
Func<int, int, int> add = (a, b) => a + b;
Predicate<int> isEven = x => x % 2 == 0;

Q. What is CancellationToken?

Exact Answer:
CancellationToken is used to cancel long-running or asynchronous operations gracefully. In Web API, if client cancels request or timeout happens, cancellation token can be passed to database calls, HTTP calls, or background operations so unnecessary processing can stop.

Q. Task in .NET Core? Why use await?

Exact Answer:
Task represents an asynchronous operation. We use await to asynchronously wait for the task to complete without blocking the current thread. This is especially useful for I/O operations like database calls, file operations, and external API calls. In ASP.NET Core, async/await improves scalability because threads are released while waiting for I/O.

Q. Array vs ArrayList?

Exact Answer:
Array is fixed-size and strongly typed, so it gives better type safety and performance. ArrayList is dynamic but stores elements as object, so it can cause boxing/unboxing and runtime casting issues. In modern C#, we prefer List<T> over ArrayList.

Q. String vs StringBuilder?

Exact Answer:
String is immutable, so every modification creates a new string object. StringBuilder is mutable and is better when we need frequent string modifications, like building large dynamic text in loops. For small fixed strings, normal string is fine; for repeated concatenation, StringBuilder is preferred.

Q. Extension methods?

Exact Answer:
Extension methods allow us to add new methods to existing types without modifying the original type. They are static methods inside static classes and use this keyword before the first parameter.
public static class StringExtensions
{
    public static bool IsNullOrEmptyEx(this string value)
    {
        return string.IsNullOrEmpty(value);
    }
}

Q. What is PUT, POST, PATCH?

Exact Answer:
POST is used to create a new resource or perform non-idempotent operation. PUT is used to update or replace the complete resource and is idempotent. PATCH is used for partial update, where only selected fields are modified.

Q. Explain OOPS concepts.

Exact Answer:
OOPS has four main concepts: Encapsulation, Abstraction, Inheritance, and Polymorphism. Encapsulation means wrapping data and behavior together and protecting internal state. Abstraction means exposing only required details. Inheritance means reusing common behavior from parent class. Polymorphism means same method/interface can have different implementations based on object type.

9. LINQ & Entity Framework

Q. What is LINQ?

Exact Answer:
LINQ means Language Integrated Query. It allows us to query collections, databases, XML, and other data sources using strongly typed C# syntax. In EF Core, LINQ queries are translated into SQL queries and executed on the database.

Q. Advantages of LINQ over Entity Framework queries?

Exact Answer:
LINQ gives strongly typed query syntax, compile-time checking, IntelliSense, readability, and composability. With EF Core, LINQ is used to write queries against DbSet, and EF translates those queries into SQL. Compared to raw SQL, LINQ is easier to maintain and refactor, but for very complex or performance-critical queries, raw SQL or stored procedure can also be used.

Q. Include keyword compared to Join?

Exact Answer:
Include is used to load related navigation properties when we need entity graph, for example Employee with Payrolls. Join is used when we want to combine data from multiple tables explicitly, usually for custom DTO or reporting. For performance, I prefer projection when only selected fields are required.
var employees = await _db.Employees
    .Include(e => e.Payrolls)
    .ToListAsync();

var data = await (from e in _db.Employees
                  join p in _db.Payrolls on e.Id equals p.EmployeeId
                  select new { e.Name, p.NetSalary })
                  .ToListAsync();

Q. Best practices for fetching/filtering data using LINQ?

Exact Answer:
I apply filters before materializing data, avoid early ToList, select only required columns using projection, use AsNoTracking for read-only queries, apply pagination for large data, avoid unnecessary Include, avoid N+1 queries, use async methods, and check generated SQL/execution plan for performance-critical queries.

10. Microservices

Q. Explain microservices architecture.

Exact Answer:
Microservices architecture breaks a large application into small, independently deployable services. Each service owns a specific business capability and can have its own database. For example, Employee Service, Payroll Service, Notification Service, and Audit Service. The benefit is independent deployment, scalability, better fault isolation, and technology flexibility. The challenges are distributed transactions, monitoring, communication failures, and operational complexity.

Q. How do you communicate data between microservices?

Exact Answer:
Microservices communicate synchronously using REST or gRPC when immediate response is required. They communicate asynchronously using message brokers like RabbitMQ, Kafka, or Pub/Sub when loose coupling and reliability are required. For critical business events, I prefer asynchronous event-based communication because it reduces direct dependency between services.

Q. How do you implement transactions in microservices?

Exact Answer:
In microservices, we avoid distributed database transactions as much as possible. Instead, we use Saga pattern where each service performs its local transaction and publishes an event. If any step fails, compensating action is triggered to undo previous steps. We also use outbox pattern, retries, idempotency, and dead-letter queues for reliability.

Q. Have you used Saga pattern?

Exact Answer:
Yes, I understand and have worked with Saga-style workflows. Saga is used to manage distributed transactions across multiple services. For example, payroll processing may involve Payroll Service, Payment Service, Notification Service, and Audit Service. If payment fails after payroll calculation, a compensating event can mark payroll as failed or reversed. Saga can be choreography-based using events or orchestration-based using a central coordinator.

Q. How do you authenticate and authorize a Web API?

Exact Answer:
I secure Web API using JWT/OAuth/OpenID Connect. Authentication validates the token, issuer, audience, expiry, and signing key. Authorization is handled using roles, claims, or policies. For sensitive APIs, I also validate user permissions at business layer, not only at controller level.

Q. If a transaction fails, how do you identify which microservice failed?

Exact Answer:
I use correlation id, distributed tracing, centralized logging, and message/event id. Every service logs the same correlation id, so we can trace the complete request flow. In message-based communication, I also check queue status, retry count, dead-letter queue, and event processing logs to identify exactly which service failed.

Q. Handling failures in microservices?

Exact Answer:
For failure handling, I use retry with exponential backoff for transient failures, circuit breaker to avoid cascading failures, timeout, fallback where possible, idempotency to safely retry operations, dead-letter queue for failed messages, and proper monitoring/alerts. I also ensure logs and traces are available with correlation id.

Q. Experience with message brokers / RabbitMQ?

Exact Answer:
Yes, I have experience with message-broker-based communication. RabbitMQ is used for asynchronous communication between services. Producer publishes message to exchange, exchange routes message to queue, and consumer reads from queue. For reliability, we use durable queues, acknowledgements, retry mechanism, and dead-letter exchange. It helps decouple services and handle load spikes.

I track error logs using structured centralized logging. Every service logs correlation id, request id, service name, endpoint, user/context, error message, and exception stack trace. Logs are pushed to tools like ELK, Splunk, Application Insights, Seq, or GCP Cloud Logging. 12. SQL Questions

Q. SQL Joins.

Exact Answer:
SQL joins are used to combine rows from two or more tables based on related columns. Inner join returns matching records from both tables. Left join returns all records from left table and matching records from right table. Right join returns all records from right table and matching records from left table. Full join returns records from both sides. Cross join returns Cartesian product.

Q. Temp table vs table variable.

Exact Answer:
Temp table is created in tempdb using #temp and is generally better for larger datasets because it supports indexes and statistics. Table variable is declared using @table and is suitable for smaller datasets. Temp tables can be altered after creation and often perform better for complex operations, while table variables are limited and should be used carefully for large data.

13. Coding Questions

Q. Move all zeroes to end in array without changing order of non-zero elements.

Exact Answer:
I will use two-pointer approach. One pointer tracks the position where next non-zero element should be placed. First, I move all non-zero elements forward while maintaining order. Then I fill remaining positions with zero. This is in-place, time complexity O(n), and space complexity O(1).
public static void MoveZeroes(int[] nums)
{
    int insertPos = 0;

    for (int i = 0; i < nums.Length; i++)
    {
        if (nums[i] != 0)
        {
            nums[insertPos] = nums[i];
            insertPos++;
        }
    }

    while (insertPos < nums.Length)
    {
        nums[insertPos] = 0;
        insertPos++;
    }
}

// Input:  [0,1,0,3,12]
// Output: [1,3,12,0,0]

Q. Palindrome program.

Exact Answer:
I will use two-pointer approach, one pointer from start and one from end. If characters do not match, it is not palindrome. If all characters match until pointers cross, it is palindrome.
public static bool IsPalindrome(string input)
{
    if (input == null) return false;

    int left = 0;
    int right = input.Length - 1;

    while (left < right)
    {
        if (char.ToLower(input[left]) != char.ToLower(input[right]))
            return false;

        left++;
        right--;
    }

    return true;
}

Q. C# using keyword.

Exact Answer:
using keyword is used to automatically dispose objects that implement IDisposable. It is commonly used with file streams, database connections, and other unmanaged resource wrappers. It ensures Dispose is called even if exception occurs.
using var connection = new SqlConnection(connectionString);
connection.Open();

Q. Method overloading.

Exact Answer:
Method overloading means having multiple methods with the same name but different parameter type, number, or order. Return type alone cannot be used for method overloading.
public int Add(int a, int b) => a + b;
public decimal Add(decimal a, decimal b) => a + b;
public int Add(int a, int b, int c) => a + b + c;
