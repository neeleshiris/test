2. Overview of Collections

Collections are used to store, manage, search, sort, and process groups of objects. In C#, collections are heavily used when we work with multiple records such as reports, users, assignments, notifications, audit logs, and configuration data.

Collection Type Description Example Use Case
Non-Generic Collections Older collections that store data as object type. ArrayList and Hashtable.
Generic Collections Type-safe collections where the type is known at compile time. List<T>, Dictionary<TKey, TValue>, HashSet<T>.
Concurrent Collections Thread-safe collections used in multi-threaded scenarios. ConcurrentDictionary for safe parallel updates.
Interview answer:
“Collections are used to manage groups of objects. In my Insurance Reporting Hub project, collections were used to store reports, users, assigned reports, notification lists, and audit history. I prefer generic collections like List<T> and Dictionary<TKey, TValue> because they are type-safe, readable, and better for performance compared to older non-generic collections.”

3. List Collection Concepts

A List<T> is a strongly typed, ordered collection. It is useful when I need to maintain a sequence of records and iterate over them. It supports dynamic resizing, index-based access, sorting, filtering, and LINQ operations.

  • List maintains insertion order.
  • Index access is O(1).
  • Searching by condition is O(n).
  • List is useful for ordered data display.
  • List is not ideal for frequent key-based lookup.

Insurance Reporting Hub Example

In the Insurance Reporting Hub, a List is useful for displaying assigned reports on a dashboard. When a user logs in, I can fetch all reports assigned to that user and display them sorted by priority or due date. 

List<ReportDto> assignedReports =
    await _reportRepository.GetAssignedReportsAsync(userId);

var sortedReports = assignedReports
    .OrderByDescending(r => r.Priority)
    .ThenBy(r => r.DueDate)
    .ToList();
Interview answer:
“I use List when I need ordered data and iteration. In my Insurance Reporting Hub project, assigned reports on the dashboard were represented as a List because users expected records to be displayed in a meaningful order, such as priority-wise or due-date-wise. However, if I need frequent lookup by user ID or report ID, I prefer Dictionary instead of repeatedly searching a List.”

4. Generic Collections

Generic collections are type-safe collections where the data type is specified at compile time. They avoid runtime casting issues and improve readability and performance.

Generic Collection Purpose Insurance Reporting Hub Example
List<T> Stores ordered items. Assigned reports list.
Dictionary<TKey, TValue> Stores key-value pairs for fast lookup. User workload lookup by UserId.
HashSet<T> Stores unique values. Unique report category IDs or unique assigned user IDs.
Queue<T> First-in-first-out processing. Report processing queue.
Stack<T> Last-in-first-out processing. Undo operations or navigation history.
Interview answer:
“Generic collections provide compile-time type safety. In my project, I used List<ReportDto> for report lists, Dictionary<int, int> for user workload mapping, and HashSet<int> when I needed unique report category IDs. Generic collections help avoid casting errors, improve readability, and make the code safer.”

5. Difference Between HashTable and Dictionary

Point HashTable Dictionary
Type Safety Not type-safe because it stores keys and values as object. Type-safe because key and value types are defined.
Namespace System.Collections System.Collections.Generic
Performance Can involve boxing and unboxing for value types. Better performance due to generics.
Compile-time Safety Errors may appear at runtime. Many errors are caught at compile time.
Modern Usage Older style and rarely preferred in modern C#. Preferred in modern C# applications.

Insurance Reporting Hub Example

In the Insurance Reporting Hub, if I need to map UserId to assigned report count, Dictionary<int, int> is better than Hashtable because it is type-safe and readable. 

Dictionary<int, int> userWorkloadMap = assignedReports
    .GroupBy(r => r.AssignedUserId)
    .ToDictionary(g => g.Key, g => g.Count());
Interview answer:
“HashTable is an older non-generic collection that stores keys and values as object, so it is not type-safe and may require boxing, unboxing, and casting. Dictionary is a generic collection, so it is type-safe and preferred in modern C# applications. In my Insurance Reporting Hub project, I would use Dictionary<int, int> to map UserId to assigned report count because it is faster, cleaner, and safer than Hashtable.”

6. Serialization

Serialization is the process of converting an object into a format that can be stored or transferred. Deserialization is the reverse process where serialized data is converted back into an object.

  • JSON serialization is commonly used in REST APIs.
  • XML serialization can be used when systems require XML format.
  • Binary serialization is generally avoided in modern API communication unless there is a specific requirement.

Insurance Reporting Hub Example

In the Insurance Reporting Hub, when Angular calls the .NET Core API, the report object is usually sent as JSON. The backend serializes response objects into JSON, and Angular receives that JSON and binds it to TypeScript models.

    public string ReportName { get; set; }
    public string Status { get; set; }
    public int AssignedUserId { get; set; }
}
Interview answer:
“Serialization is used to convert objects into a transferable format such as JSON. In my Insurance Reporting Hub project, when the backend returned assigned reports to the Angular UI, the .NET Core API serialized ReportDto objects into JSON. Angular consumed that JSON response and displayed it on the dashboard. Serialization is very important in API-based applications because frontend and backend communicate mostly through JSON.”

7. Difference Between ref and out Parameters

Point ref out
Initialization Before Passing Variable must be initialized before passing. Variable does not need to be initialized before passing.
Assignment Inside Method Method may or may not assign a new value. Method must assign a value before returning.
Purpose Used when input value is required and may be modified. Used when method needs to return additional values.

ref Example

public void IncreaseWorkload(ref int workload)
{
    workload = workload + 1;
}

int currentWorkload = 5;
IncreaseWorkload(ref currentWorkload);

out Example

public bool TryGetAssignedUser(int reportId, out int assignedUserId)
{
    assignedUserId = 101;
    return true;
}

int userId;
bool found = TryGetAssignedUser(5001, out userId);
Interview answer:
“The ref parameter requires the variable to be initialized before passing it to the method, and the method can modify that value. The out parameter does not require initialization before passing, but the method must assign a value before returning. In real projects, out is commonly used in Try-pattern methods, such as TryGetAssignedUser, where the method returns a boolean status and also outputs a value.”

8. How a Constructor Works

A constructor is a special method of a class that is automatically called when an object is created. It is mainly used to initialize fields, inject dependencies, validate required values, or set default state.

  • Constructor name is the same as the class name in C#.
  • Constructor does not have a return type.
  • It is called automatically when an object is created.
  • It can be parameterless or parameterized.
  • In Angular and .NET Core, constructors are often used for dependency injection.

C# Constructor Example

public class ReportAssignmentService
{
    private readonly IUserRepository _userRepository;

    public ReportAssignmentService(IUserRepository userRepository)
    {
        _userRepository = userRepository;
    }
}

Angular Constructor Example

export class ReportDashboardComponent {
  constructor(private reportService: ReportService) {}
}
Interview answer:
“A constructor is used to initialize an object when it is created. In my Insurance Reporting Hub project, constructors were mainly used for dependency injection. For example, ReportDashboardComponent received ReportService through the constructor, and ReportAssignmentService received repository dependencies through the constructor. This approach makes the code loosely coupled and easier to test.”

10. In Angular: What is Dependency Injection?

Dependency Injection in Angular is a design pattern where Angular provides dependencies such as services to components or other services. The component does not create the service manually. Instead, Angular Injector creates or reuses the service instance and injects it through the constructor.

Component is created ↓ Angular reads constructor dependencies ↓ Angular checks provider registration ↓ Angular creates or reuses service instance ↓ Service is injected into component ↓ Component uses service methods
@Injectable({
  providedIn: 'root'
})
export class ReportService {
  constructor(private http: HttpClient) {}
}

export class ReportDashboardComponent {
  constructor(private reportService: ReportService) {}
}
Interview answer:
“Dependency Injection in Angular means Angular provides the required dependency instead of the component creating it manually. In my Insurance Reporting Hub project, ReportDashboardComponent did not create ReportService using the new keyword. Angular injected ReportService through the constructor. This made the component loosely coupled, easier to test, and easier to maintain.”

11. If Two Components A and B Use the Same Service, Will Private Field Update Reflect in Both?

The answer depends on how the service is registered. If the service is registered at root level using providedIn: 'root', Angular creates a singleton instance. In that case, both Component A and Component B use the same service instance. If shared state inside that service is updated through public methods or exposed through Observables, both components can receive the updated value.

However, if the service is provided separately in each component’s providers array, Angular creates separate instances for each component. In that case, an update in Component A will not reflect in Component B. 

@Injectable({
  providedIn: 'root'
})
export class ReportStateService {
  private assignedCountSubject = new BehaviorSubject<number>(0);
  assignedCount$ = this.assignedCountSubject.asObservable();

  updateAssignedCount(count: number): void {
    this.assignedCountSubject.next(count);
  }
}
Interview answer:
“If Component A and Component B use the same root-level service, then they share the same service instance. If a private field is updated inside that service and exposed through a public method or Observable, both components can see the updated value. In my Insurance Reporting Hub project, this was useful for dashboard count and notification badge updates. However, if the service is registered separately at component level, each component gets a different instance, and the updated value will not be shared.”
Important point:
A private field cannot be accessed directly by components. It should be exposed through a public method, getter, Observable, Subject, or BehaviorSubject.

13. Subject and BehaviorSubject

Subject

Subject is both an Observable and an Observer. It can emit values using next(), and multiple subscribers can listen to those values. Subject is useful for event-based communication when we do not need to store the latest value. 

@Injectable({
  providedIn: 'root'
})
export class ReportRefreshService {
  private refreshSubject = new Subject<void>();
  refresh$ = this.refreshSubject.asObservable();

  triggerRefresh(): void {
    this.refreshSubject.next();
  }
}
Subject interview answer:
“Subject is useful when I need event-based communication. In my Insurance Reporting Hub project, after a report is assigned from one component, I can use Subject to notify the report list component to refresh. Since I only need to broadcast an event and do not need to store the latest value, Subject is a good choice.”

BehaviorSubject

BehaviorSubject is a special type of Subject that requires an initial value and stores the latest emitted value. When a new subscriber subscribes, it immediately receives the latest value. It is useful for shared state. 

@Injectable({
  providedIn: 'root'
})
export class ReportAssignmentStateService {
  private assignedCountSubject = new BehaviorSubject<number>(0);
  assignedCount$ = this.assignedCountSubject.asObservable();

  updateAssignedCount(count: number): void {
    this.assignedCountSubject.next(count);
  }

  getCurrentAssignedCount(): number {
    return this.assignedCountSubject.value;
  }
}
BehaviorSubject interview answer:
“BehaviorSubject is useful when I need to maintain and share the latest state. In my Insurance Reporting Hub project, I can use BehaviorSubject for assigned report count, notification count, selected report, or logged-in user context. The benefit is that when a new component subscribes, it immediately receives the latest value.”

Subject vs BehaviorSubject

Point Subject BehaviorSubject
Initial Value Not required. Required.
Stores Latest Value No. Yes.
New Subscriber Gets Previous Value No. Yes, latest value.
Best Use Event notification. Shared state.
Project Example Refresh report list after assignment. Maintain dashboard count or notification count.

14. Write a Palindrome Series and Explain Time Complexity

A palindrome is a value that reads the same forward and backward, such as madam, level, radar, or 121. In interviews, palindrome questions are asked to check loop logic, string handling, edge cases, and time complexity understanding.

String Palindrome Using Two Pointers

public static bool IsPalindrome(string input)
{
    if (string.IsNullOrWhiteSpace(input))
        return false;

    int left = 0;
    int right = input.Length - 1;

    while (left < right)
    {
        if (char.ToLower(input[left]) != char.ToLower(input[right]))
            return false;

        left++;
        right--;
    }

    return true;
}

Time complexity is O(n) because each character is checked at most once. Space complexity is O(1) because no extra string is created.

Number Palindrome

public static bool IsNumberPalindrome(int number)
{
    if (number < 0)
        return false;

    int original = number;
    int reversed = 0;

    while (number > 0)
    {
        int digit = number % 10;
        reversed = reversed * 10 + digit;
        number = number / 10;
    }

    return original == reversed;
}

Palindrome Series Example

public static List<int> GetPalindromeNumbers(int start, int end)
{
    List<int> result = new List<int>();

    for (int i = start; i <= end; i++)
    {
        if (IsNumberPalindrome(i))
        {
            result.Add(i);
        }
    }

    return result;
}

If the range has n numbers and each number has d digits, the time complexity is approximately O(n * d). If the number of digits is small and fixed, it can be considered close to O(n).

Interview answer:
“For palindrome checking, I prefer the two-pointer approach for strings because it gives O(n) time and O(1) space. For palindrome series, I check each number in the given range and apply number palindrome logic. If there are n numbers and each number has d digits, the complexity is O(n * d). In real projects, similar logic can be applied in validation scenarios, although palindrome itself is usually an interview problem.”

15. Difference Between Observable and Promise

Point Promise Observable
Values Returns a single future value. Can emit zero, one, or multiple values over time.
Execution Eager; starts immediately. Lazy; starts when subscribed.
Cancellation Not easily cancellable. Can be cancelled using unsubscribe.
Operators Limited to then, catch, finally. Supports RxJS operators like map, switchMap, debounceTime, retry, catchError.
Angular Usage Can be used for one-time async result. Default return type of Angular HttpClient.

Insurance Reporting Hub Example

In the Insurance Reporting Hub, report search is a good Observable use case. When the user types in the search box, Observable operators like debounceTime and switchMap help reduce unnecessary API calls and cancel previous requests. 

reports$ = this.searchControl.valueChanges.pipe(
  debounceTime(300),
  distinctUntilChanged(),
  switchMap(searchText =>
    this.reportService.searchReports(searchText || '')
  )
);
Interview answer:
“A Promise represents a single future value, whereas an Observable represents a stream of values over time. Angular HttpClient returns Observable by default because Observables support cancellation, multiple emissions, and RxJS operators. In my Insurance Reporting Hub project, I used Observables for report search, dashboard count updates, and component communication. Promise is useful for simple one-time async operations, but Observable is more powerful for Angular applications.”

16. What is an Interceptor in Angular?

An Angular Interceptor is a service that intercepts HTTP requests and responses. It is commonly used to add authentication tokens, handle errors globally, log requests, show or hide loaders, modify headers, or handle unauthorized responses.

  • Add JWT token to every outgoing API request.
  • Handle 401 Unauthorized responses globally.
  • Show and hide global loader.
  • Log request and response details.
  • Handle common API errors at one place.

Insurance Reporting Hub Example

In the Insurance Reporting Hub, most APIs require authentication. Instead of manually adding the token in every service method, an interceptor can attach the JWT token to every request. 

@Injectable()
export class AuthInterceptor implements HttpInterceptor {
  constructor(private authService: AuthService) {}

  intercept(
    request: HttpRequest<any>,
    next: HttpHandler
  ): Observable<HttpEvent<any>> {

    const token = this.authService.getToken();

    if (token) {
      request = request.clone({
        setHeaders: {
          Authorization: `Bearer ${token}`
        }
      });
    }

    return next.handle(request);
  }
}

Registering Interceptor

providers: [
  {
    provide: HTTP_INTERCEPTORS,
    useClass: AuthInterceptor,
    multi: true
  }
]
Interview answer:
“An Angular Interceptor is used to intercept HTTP requests and responses. In my Insurance Reporting Hub project, I would use an interceptor to attach the JWT token to every API request, handle unauthorized errors globally, and optionally manage a global loader. This avoids repeating token logic in every service method and keeps API services clean.”
Senior point:
Interceptors should not contain business logic. They should handle cross-cutting concerns such as authentication, logging, error handling, and loader management.
