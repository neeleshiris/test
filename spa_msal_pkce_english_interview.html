White Background · Simple English Interview Notes

SPA Authentication Flow using MSAL.js, Azure AD / Azure AD B2C and PKCE

Goal: Explain clearly in an interview where the token is generated, what authorization code means, what PKCE is, and what code verifier/code challenge means.

SPAMSAL.jsAzure ADAzure AD B2CAuthorization Code FlowPKCEJWT

1. One-Line Interview Answer

Say this:

“In a SPA, I use MSAL.js. MSAL redirects the user to Azure AD or Azure AD B2C login page. After successful login, Azure AD/B2C returns an authorization code to the SPA redirect URI. MSAL then sends this authorization code along with the code verifier to the token endpoint. Azure AD/B2C validates PKCE and then issues the ID token and access token. The SPA sends the access token to the backend API, and the API validates the JWT before returning data.”

2. Where Is the Token Generated?

The token is not generated inside the browser or inside the SPA.

The token is generated by Azure AD / Azure AD B2C at the token endpoint. MSAL only receives the token and stores it in its cache.

Login is successful
        ↓
SPA receives authorization code
        ↓
MSAL sends authorization code + code_verifier to /token endpoint
        ↓
Azure AD/B2C generates ID token + access token
        ↓
MSAL receives tokens

3. Full Flow: SPA + MSAL + Azure AD/B2C

1
User opens the SPA
The React/Angular application loads in the browser.
2
User clicks Login
The SPA calls msal.loginRedirect() or msal.loginPopup().
3
MSAL creates PKCE values
MSAL creates a random code_verifier and creates a hashed value called code_challenge.
4
MSAL redirects to /authorize
MSAL sends the user to Azure AD/B2C authorize endpoint with the code_challenge.
5
User completes login
The user enters credentials, completes MFA, or completes sign-up depending on the policy/user flow.
6
Authorization code is returned
Azure AD/B2C sends a temporary authorization code to the SPA redirect URI. At this point, the SPA does not have tokens yet.
7
MSAL calls /token
MSAL sends the authorization code and the original code_verifier to the token endpoint.
8
Azure AD/B2C validates PKCE
The server checks whether SHA256(code_verifier) matches the earlier code_challenge.
9
Tokens are issued
If the verifier matches, Azure AD/B2C generates and returns the ID token and access token.
10
SPA calls the API
The SPA calls the backend API with Authorization: Bearer access_token.
11
API validates the JWT
The API validates signature, issuer, audience, expiry, scopes, and roles.

4. PKCE Simple Meaning

PKCE = Proof Key for Code Exchange

Simple meaning: “PKCE proves that the same application that started the login flow is the one exchanging the authorization code for tokens.”

A SPA runs in the browser, so it cannot safely store a client secret. That is why SPA authentication uses PKCE instead of a client secret.

5. Code Verifier vs Code Challenge

TermSimple MeaningWhen is it used?
code_verifierA random secret string created by MSAL.Sent in the token request.
code_challengeA hashed version of the code verifier.Sent in the login/authorize request.
authorization codeA temporary code returned after successful login.Exchanged for tokens at the token endpoint.

6. The Most Important Line to Remember

Remember this:

code_challenge = sent during login start to /authorize
code_verifier  = sent while getting tokens from /token
token          = generated by Azure AD/B2C token endpoint

7. Example Requests: Simple View

A. Authorize Request: Login Start

GET https://tenant.b2clogin.com/.../oauth2/v2.0/authorize
  ?client_id=spa-client-id
  &response_type=code
  &redirect_uri=https://app.com
  &scope=openid profile api.read
  &code_challenge=HASH_OF_CODE_VERIFIER
  &code_challenge_method=S256
  &state=random-state
  &nonce=random-nonce

The code_challenge is sent here.

B. Token Request: Code Exchange

POST https://tenant.b2clogin.com/.../oauth2/v2.0/token

grant_type=authorization_code
client_id=spa-client-id
code=AUTHORIZATION_CODE_FROM_LOGIN
redirect_uri=https://app.com
code_verifier=ORIGINAL_RANDOM_SECRET

The code_verifier is sent here. If it matches, tokens are returned.

9. API Validation Answer

The backend API validates the access token:

  • Signature — confirms the token came from trusted Azure AD/B2C.
  • Issuer — confirms the correct tenant/policy issued the token.
  • Audience — confirms the token is meant for this API.
  • Expiry — confirms the token is not expired.
  • Scopes/Roles — confirms the user has the required permission.

10. Do Not Say This

  • ❌ “The SPA generates the token.”
  • ❌ “After login, the access token directly comes in the URL.”
  • ❌ “We store a client secret in the SPA.”
  • ❌ “We send the ID token to the API.”

Correct: The SPA sends the access token to the API. The token is generated by Azure AD/B2C token endpoint. A SPA does not store a client secret; it uses PKCE.

11. Final 30-Second Interview Answer

“In SPA authentication, we use MSAL.js. When login starts, MSAL creates a code verifier and a code challenge. MSAL redirects the user to the Azure AD/B2C authorize endpoint with the code challenge. After successful login, Azure AD/B2C returns an authorization code to the SPA. MSAL then sends the authorization code and the original code verifier to the token endpoint. Azure AD/B2C validates the verifier against the earlier challenge and then issues the ID token and access token. The SPA calls the backend API using the access token, and the API validates the JWT before returning data.”
